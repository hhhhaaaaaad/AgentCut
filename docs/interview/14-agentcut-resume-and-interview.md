## 1. 一页简历候选稿

**AgentCut｜AI 视频智能剪辑平台｜个人项目**

**技术栈：** Java 17、Spring Boot、Python、FastAPI、LangChain/LangGraph、VLM、PySceneDetect  
**GitHub：** https://github.com/hhhhaaaaaad/AgentCut

**项目介绍：** 面向短视频创作者，结合多模态素材理解与多 Agent 剪辑决策，辅助生成可人工编辑的短视频剪辑方案。

**业务痛点：** 人工浏览与选材耗时，直接压缩素材容易误删铺垫、切断语句。

**核心工作：**

1. **多模态素材理解：** 针对仅靠转写难以判断画面内容的问题，整合 VLM 视觉分析、ASR 语音转写、VAD 与场景检测，按场景抽帧并依据视频时长设置采样预算，形成包含场景描述、章节、关键句及冗余区间的结构化报告，为片段筛选提供依据。
2. **剪辑决策约束：** 针对模型直出方案易出现区间错误与关键内容误删的问题，构建分析、导演、质检协作链路，以五维评审驱动最多 3 轮生成与修订，结合 12 项规则检查、关键场景恢复及异常降级，对剪辑方案进行结构与执行约束检查。

实际投递可将项目介绍与痛点合成一句，避免背景占两行：

> 面向短视频创作者，针对素材浏览、选材与内容组织成本，结合多模态分析和受约束剪辑决策，辅助生成可编辑方案。

## 3. 关键取舍

- AgentWrite 继续承担记忆、评测与可靠异步执行主线；AgentCut 用两点证明多模态理解和模型输出边界，不重复展开任务编排、DDD 或框架配置。
- 保留“AI 视频智能剪辑平台”名称，用“辅助生成可编辑方案”界定当前能力；不更换为知识管理、培训或课程整理业务。
- 不写“分析、导演、质检三 Agent 全部由 LangGraph 编排”：实际分析层含 Timeline/Narration 专家和 VLM，导演/QA 是普通循环；写协作职责更准确。
- “动态抽帧”替换为“按场景抽帧、时长相关采样预算”。现有代码并非语义自适应抽帧，场景超预算时还会丢弃部分场景区间。
- 12 是已有检查项目数，3 是循环上限，均不是效果指标。部分规则只警告，不是 12 条全部强制。
- 不写“精确句级时间戳”：云端 ASR 文本对应 VAD 合并块；本地 FunASR 有 sentence_info 解析路径，但精度未实测。
- FunASR 当前是本地降级路径，不宜写成唯一 ASR 主引擎。主技术栈写 ASR 或正文语音转写即可，能解释本地路径时可补 FunASR。
- 弱化 FFmpeg 成片，但不隐藏项目有 Java 后端、方案编辑与渲染执行链路；被问时如实说明。

## 4. 一分钟项目介绍

> AgentCut 是面向短视频创作者的视频智能剪辑项目，目标是辅助筛选素材和组织内容，不承诺一键高质量成片。我主要做了两块：一是结合语音转写、VAD、场景抽帧和 VLM，将画面与口播信息整理成结构化报告；二是让分析、导演和质检协作生成剪辑方案，通过五维评审做有限轮次修订，再结合规则检查和部分关键场景恢复处理异常。它与 AgentWrite 的区别在于多模态理解和剪辑决策边界，而不是重复建设异步任务框架。目前自动成片质量仍不理想，规则能检查区间和操作，却不能证明语义完整。因此我不宣称质量提升，下一步最需要补的是同素材下 ASR-only、多模态及单/多 Agent 对照，并用人工误删和修正成本评价收益。

## 5. 面试追问

### 为什么要多模态？口播不靠 ASR 就够了吗？

ASR 能提供讲解内容，但无法直接判断屏幕演示、动作、表情或画面变化。VLM 提供补充视觉依据，场景与抽帧建立观察位置。对纯口播，视觉增益可能很小，不能因为接入 VLM 就断言更好；需要 ASR-only 对照，同时观察调用成本。当前关键句与论点主要来自讲解分析，不能把它们全部归因于 VLM。

### VAD 能解决切断句子吗？

不能。VAD 判断声学语音区间，停顿不等于语义结束；当前云端路径会合并语音块并对长块按 30 秒切分。应区分“真实音频块时间”与“句内精确位置”。基于语义单元和可靠对齐的决策是后续设计，不是已有保证。

### 为什么多 Agent？比单 Agent 好在哪里？

已实现的价值是职责分离：分析提供依据，导演输出方案，质检提供问题反馈，便于查看错误来自哪一环。质量收益还未通过真实对照验证。多 Agent 也增加调用成本，且导演与质检可能依赖同一份不完整报告，形成相关性错误；不能用 QA 分数证明优于单 Agent。

### 五维评分和 12 条规则分别做什么？

五维包括时间轴连续性、内容完整性、节奏、口播画面匹配和可执行性，是模型评审信号。规则检查区间越界、重叠、裁切、字幕、引用和时长等；其中关键句覆盖、超速等只是 warning。规则只覆盖声明的检查项，不负责审美或完整语义判断。

### 为什么规则通过还可能有坏方案？

合法时间区间仍可能切在句子中间；保留结论却删掉条件也可能改变原意。现有关键内容检查只覆盖部分关键句，QA 又未拿到完整转写和帧图。补充构造验证还发现恢复场景会引入重叠、fallback 可能不通过同一时长校验，所以我不会把它表述成“保证可执行/保证完整”。

### “必须保留”和删减预算是否已经是硬约束？

删减预算和完整句子边界主要是 Prompt 指引，不是程序硬门禁。已有代码确实会恢复部分关键场景，但恢复粒度粗，可能带来重叠或超时长。应分别说“Prompt 引导”和“程序恢复”，不能混成完整内容保护。

### 成片质量怎么样？是不是只有方案没有实际执行？

项目有 FFmpeg 渲染链路，但自动成片质量目前仍不理想，出现过过度删减、铺垫缺失和句子切断。我的简历强调素材理解、方案生成和约束机制，不把执行成功等同高质量。历史视频问题与先前构造用例是不同证据，尚未做统一真实基线来证明修复收益。

### 用了 LangGraph，是不是可以恢复长任务？

现在 LangGraph 仅编排分析阶段，compile 未配置持久化 checkpointer。导演/质检是普通循环，Python job 状态也在内存；不能宣称阶段持久恢复。Java MySQL 仓储存在也不等于 Python 执行恢复。

## 7. 最值得补测的指标

按简历价值优先级：

1. **人工修正时间与修改次数**：相同主题、时长和质量要求，对比规则、单 Agent、当前多 Agent，直接对应辅助剪辑价值。
2. **关键内容误删、上下文缺失、原意改变**：人工标注任务相关内容及必要依赖，按视频报告，保留全部失败，不以 QA 分数替代。
3. **VLM 增益与成本**：ASR-only 与 ASR+VLM 同素材对照；区分纯口播和依赖视觉的样本，报告定位收益、调用成本及耗时。
4. **规则的实际作用与剩余失败**：按规则统计捕获错误、误报、修复后新增问题和最终方案违反率。区分规则通过率与实际渲染成功率。

使用授权小素材集、固定版本和留出样本；重复运行并报告失败/降级。没有收益就写未证实，不为简历设定提升数字。
