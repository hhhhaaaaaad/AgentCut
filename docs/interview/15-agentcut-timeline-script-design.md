# AgentCut 时间轴剪辑脚本设计方案

日期：2026-10-17  
状态：脚本展示格式已获用户确认；具体契约、实施范围与验收方案待评审。  
本轮仅输出设计文档，不修改 AgentCut 源码，不启动开发或模型调用，不提交 Git。  
本方案补充既有主题提炼设计，不覆盖原设计和简历稿。素材索引、ID 决策、确认绑定等是拟新增能力，不是当前成果。

## 1. 产品目标与已确认形式

面向短视频创作者，针对人工浏览、定位片段和组织内容的成本，将素材分析转化为能直接指导剪辑工作的脚本。

主产物不是笼统的分析总结，也不是“一键高质量成片”，而是：

> 标明取材位置、成片顺序、原声内容、画面依据、包装建议及切点风险的可编辑时间轴脚本。

用户已确认表格列：

**镜号｜成片时间｜原素材入点—出点｜画面｜原声／声音｜字幕与包装｜剪辑备注**

第一阶段仍是单段语音主导素材的主题提炼，默认单主题、原顺序、原速、硬切，不扩展复杂多素材叙事。镜号是脚本行的展示序号，不表示素材中实际有新镜头，也不等同于场景检测编号。

## 2. 架构取舍

| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| 直接让模型生成 Markdown 表格 | 容易演示 | 时间易编造，难统一编辑与校验 | 仅适合草案，不作为正式方案 |
| 让模型分别生成表格和执行 JSON | 两类用户都能使用 | 两份产物易不一致 | 不推荐 |
| 结构化脚本快照派生表格和执行 Plan | 引用、时间、编辑与版本可对账 | 需要受限决策与映射组件 | 推荐 |

逻辑上的单一事实来源是已保存的脚本快照，包含决策、索引版本、受限操作与建议；表格和执行 Plan 是派生视图，不独立编辑存档。物理存储复用现有方案版本和分析报告，不新建任务框架。

现有 Plan 1.0 继续作为执行投影；它缺少画面证据、原文来源、包装建议和成片时间，不宜直接塞入新字段。新脚本契约独立标记 scriptSchemaVersion，通过版本元信息关联执行投影；旧 Plan 保留读取和既有功能，但不得伪装成引用完整的新脚本。

## 3. 用户交付结构

### 3.1 脚本头信息

| 字段 | 要求 |
|---|---|
| 片名、主题、剪辑目标 | 模型可建议，用户可编辑；片名不是原素材事实 |
| 源素材 | 文件展示名、assetId、内容 hash，不暴露服务端文件路径 |
| 方案版本 | scriptId、服务端 revision、索引版本、生成时间 |
| 成片要求 | maxDuration、画幅、原速/硬切等明确设置 |
| 预计时长 | 程序计算，并标明是计划值而非实际渲染实测值 |
| 状态 | 草稿、需复核、可确认、已确认，执行状态另列 |
| 风险摘要 | 对齐粗糙、转写疑点、视觉缺失、依赖风险、未执行包装 |

默认不要求填满目标时长。“最多 60 秒”是硬上限；“期望 60 秒”是偏好，必须在入参中区分。

### 3.2 脚本表格字段来源

| 表格列 | 结构化字段 | 谁负责 | 限制 |
|---|---|---|---|
| 镜号 | shotNo + rowId | 程序生成展示序号；rowId 稳定 | 改顺序可重编号，QA/编辑仍引用 rowId |
| 成片时间 | outputRange | 程序累计 | 用户和模型不能直接填写 |
| 原素材入点—出点 | sourceParts | 索引映射 | 展示 asset + 入出点，模型不能生成自由时间 |
| 画面 | visualEvidence + treatmentNote | VLM 证据/人工确认；建议单列 | 区分“看到了什么”和“建议怎么处理” |
| 原声／声音 | spokenQuotes + audioTreatment | 原转写引用；受限音频策略 | 不把模型摘要写成受访者原话 |
| 字幕与包装 | captionCues + packagingSuggestions | 字幕取原文和对齐；包装可建议 | 原声字幕与标题文案分开 |
| 剪辑备注 | narrativeRole、reason、riskRefs、cutNotes | 模型建议、规则风险与人工备注 | “必须保留”备注不自动等于系统锁定 |

点击源区间可定位播放；点击成片时间查看该行在计划中的位置。首版不要求开发完整 NLE 时间线或视频合成预览。

### 3.3 一行是什么

一行表示成片中连续播放的一个编辑片段，可由相邻完整语义单元合并形成。不同源区间不连续时拆成不同脚本行，不能把中间已删除部分藏在一个入出点跨度里。

同一行跨多个场景时可关联多个视觉证据，不为适应表格强拆句子。无可靠句内对齐时保留较粗片段并告警，不编造更精确入出点。

## 4. 示范脚本

以下为虚构采访示例，只演示结构，不是项目实际结果，也不证明任何真实切点或语速。

片名：为什么你剪的视频越短，越不好看？  
源素材：采访_剪辑师经验.mp4，约 5 分钟  
成片要求：最多 60 秒、9:16、原声访谈、原速、硬切  
剪辑目标：完整表达“问题 → 案例 → 建议”。  
预计时长：60 秒。包装项均为人工建议，不承诺当前引擎执行。

| 镜号 | 成片时间 | 原素材入点—出点 | 画面 | 原声／声音 | 字幕与包装 | 剪辑备注 |
|---|---|---|---|---|---|---|
| 01 | 00:00–00:06 | 00:18–00:24 | 受访者正面镜头 | “视频不是剪得越短越好，而是让观众更容易看懂。” | 原声字幕；建议标题“剪得短，不等于剪得好” | 完整保留“不是……而是……” |
| 02 | 00:06–00:16 | 00:42–00:52 | 受访者继续讲解 | “很多新手为了加快节奏，会把解释背景的几句话全部删掉。” | 原声字幕；建议强调“解释背景” | 原速，硬切衔接 |
| 03 | 00:16–00:30 | 01:15–01:29 | 受访者举例 | “比如我先介绍一个人，后面再说‘他为什么这么做’。如果介绍被删了，观众就不知道‘他’是谁。” | 原声字幕；建议强调“他是谁？” | 案例整体保留，试听尾音 |
| 04 | 00:30–00:44 | 02:06–02:20 | 受访者解释方法 | “所以，删之前先判断：这句话是在重复，还是在给后面的内容提供必要信息。” | 原声字幕；建议提示“重复信息 / 必要铺垫” | 保留两个判断项 |
| 05 | 00:44–00:54 | 03:10–03:20 | 受访者总结 | “可以删停顿、口误和重复，但定义、条件和结论之间的关系，要尽量保留。” | 原声字幕；建议关键词分组 | 保留“但”及限定内容 |
| 06 | 00:54–01:00 | 04:02–04:08 | 受访者结束观点 | “好的剪辑，是减少理解成本，不是单纯减少秒数。” | 原声字幕；建议收尾文字“减少理解成本” | 不额外编造口播；如需延时字卡则需新版本重算 |

表外补充：

- 删减说明：分别标注明确删除的冗余/寒暄和未选择的主题外内容；未选中不等于有害或应删除。
- 切点复核：检查首字、尾音、定义、条件、否定与问答关系。
- 包装执行清单：建议、用户接受、已加入受支持操作、人工待制作分别列示。
- 无视觉证据时写“视觉未验证”，不能为填满画面列编造表情、动作或镜头。

## 5. 时间与素材契约

### 5.1 时间规则

- 内部使用整数毫秒与明确媒体时间基准，区间统一左闭右开 `[startMs,endMs)`。
- 表格默认显示 `HH:MM:SS.mmm`；示例整秒为阅读简写，不能用舍入后的显示值回写执行参数。
- 第一行 outputStartMs=0；后续行开始时间等于上一行结束时间；首版没有隐式空白或转场重叠。
- 原速硬切：outputDurationMs = endMs - startMs；脚本总时长等于所有行时长之和。
- 媒体/帧量化由程序按实际时间基准完成，之后再次检查单元覆盖和时长；不硬编码 1/30 秒。
- 计划时长与实际渲染时长分开保存。首版测试容差采用两帧对应时长与 50ms 中的较大值，仅用于编码结果对账；计划硬上限本身不允许借容差超标。
- 未来有变速/转场/独立字卡时才升级时长编译规则，首版遇到这些执行要求明确拒绝，不套用简单累计公式。

### 5.2 素材索引

延续 MaterialIndex 建议：assetId、源 hash、indexVersion、unitId、原文、start/end、timingQuality、转写来源、scene/frameRefs 和上下文依赖。

模型只选择单元引用，不编辑索引时间。源素材变更、ASR 重跑、手工对齐均产生新索引版本，旧引用不可静默重映射。

已有云端 ASR 绑定音频块，不能从文本标点直接推算精确句子位置。coarse 单元只能整体取用；边界疑似切断时扩大到可信邻界或进入人工复核。严重缺失/模拟转写不能成为可确认的真实剪辑脚本。

## 6. 结构化脚本契约

建议契约名 EditingScript，不是新的任务实体。关键结构：

| 层级 | 字段与约束 |
|---|---|
| 身份 | scriptSchemaVersion、scriptId、revision、projectId |
| 输入 | assetRef、indexRef、target、inputHash |
| 行列表 | rows，非空；每行 rowId 唯一，sourceUnitRefs 非空，原序原速 |
| 派生数据 | sourceParts、outputRange、spokenQuotes、visualEvidence；由映射器回填 |
| 决策解释 | narrativeRole、selectionReason、dependencyRefs |
| 操作 | executableActions，严格白名单，由能力校验准入 |
| 人工建议 | packagingSuggestions/manualNotes，不作为执行指令 |
| 字幕 | captionCues，来源引用、输出全局时间和对齐质量 |
| 校验 | validationReport、riskItems、reviewHash、status |

DirectorDecision 是受限输入：rowId、sourceUnitRefs、内容作用、理由和包装建议；时间、原声和原路径为只读派生字段。拒绝模型额外输出的自由区间、伪造原话、任意执行命令。

每个包装建议有独立 suggestionId、类型、文案、状态，状态为 PROPOSED/ACCEPTED_MANUAL/COMPILED/REJECTED。用户接受建议不等于引擎已执行；只有转为受支持 executableAction 并通过校验，才能标 COMPILED。

首版自动操作限定片段选择/删除、原声保留及可靠对齐下的普通字幕。关键词高亮、标题动画、独立字卡、B-roll、音乐均可人工建议，不自动执行。若用户要求其自动执行，应返回不支持，而不是偷偷忽略。

首版只读“原声”区，修改识别错误通过转写校正并生成新索引版本；用户自写标题在包装区。完整原文可展开查看，预览缩略必须明确标“摘要”。

## 7. 字幕与画面的证据边界

### 字幕

普通口播字幕取索引转写，不由导演改写。不能把一个 30 秒块文本匹配到其中 5 秒而宣称同步字幕。

字幕 cue 使用成片全局时间；编译到现有 OpSubtitle 时减去所属行 outputStart，转换为段内输出时间。跨行 cue 拆分需有对应对齐依据，没有则提示人工处理。

SRT 是字幕侧产物，不替代剪辑脚本。首版仅可靠句级对齐可导出普通 SRT；关键词高亮等不属于 SRT 承载能力，不宣称可自动导入完成。

### 画面

画面事实记录 observedDescription、frameRefs、采样时间与来源；单帧只支持对该帧的观察，不能据此保证整个片段动作/表情持续。

处理建议与事实分开：例如“人物正面镜头”来自证据，“建议竖屏裁切”来自建议。竖屏无法保证保留主体时提示人工调整，不默认居中裁切成功。

视频转写和画面文字是非可信输入，不得改变系统权限或变成任意工具指令。素材外发模型需授权，不使用企业敏感素材做展示。

## 8. 复用现有链路

```text
已有分析工具/专家
  → 版本化素材索引与原始证据
  → 现有导演输出受限 Decision
  → ScriptAssembler 映射原文、时间、视觉引用
  → 程序校验
  → 现有 QA 结合原文及相邻上下文评审
  → 保存合格脚本快照
  → React 时间轴脚本表 / Markdown / CSV
  → 人工编辑、重新校验、确认版本
  → 可选 Plan 1.0 执行投影与字幕侧产物
```

Python 负责素材理解、候选和语义建议；Java 负责资产身份、版本保存和最终准入。时间计算规则不允许三端各自实现一套：定义统一规范及跨语言 golden fixture，Java 保存/导出前重算核对，前端只格式化显示。

当前 app/schemas/plan.py、前端 types/plan.ts 有时间区间和操作，无可读脚本元信息；现有导演/QA 可渐进改造，不新增“脚本 Agent”。现有内存/MySQL 仓储、回调、版本机制存在不完整边界，沿用前序核实，不因本设计宣称已修复。

## 9. 编辑、版本与确认

首版交互：源片段定位、全文展开、删除/补回单元、编辑标题/备注、查看风险、保存和导出。原时间/成片时间只读；原顺序为约束，不默认开放拖动重排。

行删除、单元合并/补回后，全部重算成片时间、字幕引用和依赖；旧 QA 结果失效。内容与包装建议修改均保存新 revision，接受建议也留痕。

保存带 expectedRevision，冲突返回 409；晚到 AI 结果保存为候选，不覆盖人工版本。所有脚本导出文件带 revision/indexVersion/scriptHash。

确认绑定完整脚本版本、素材 hash、索引、约束与校验版本。NEEDS_REVIEW 可导出带醒目“未确认”标记的草稿，不能直接确认执行；用户完成风险处理后重新校验。

SCRIPT_CONFIRMED 与 executionReady 分开：可确认用于人工剪辑的脚本，不等于自动引擎支持全部建议。机器执行只使用显式执行清单，清楚列出人工待完成包装。

使用现有任务体系补必要的终态进度守卫、回调身份和原子提交；阶段恢复、取消、MQ 等不作为本次脚本格式交付前提，也不默认新增。

## 10. 校验与异常边界

### 硬校验

合法资产、索引和 unitId；区间合法；行非空；源区间无重复重叠；原序约束；成片时间连续且总时长正确；字幕引用和时间合法；受限操作；风险状态与确认一致。

程序保证原声引用来自索引，不保证 ASR 完全正确；程序保证已声明依赖覆盖，不保证模型未漏报语义依赖。

### 语义/人工检查

定义/指代/条件/否定/因果/问答依赖，切点首尾音，转写准确性，画面建议适用性，包装与原意一致性。QA 分数不是效果证明，高分不覆盖硬错误。

| 异常 | 行为 |
|---|---|
| 视觉缺失但语音可信 | 标明 ASR-only，画面未验证；不编造视觉内容 |
| 粗对齐或疑似切断 | 保留粗区间并 NEEDS_REVIEW，人工试听/校正 |
| 原文引用不匹配 | 拒绝作为原声，不能以“模型总结”替换 |
| 必保依赖导致超上限 | 反馈冲突，调整目标或选择；不静默删依赖/加速 |
| 预算耗尽/QA 失败 | 保留之前硬合格候选并列风险，没有合格候选则失败 |
| 修复、fallback、人工修改 | 全量重映射与校验，不绕过门禁 |
| 索引更新、版本冲突 | 拒绝旧引用或保存候选分支，不覆盖 |
| 要求未支持包装自动执行 | 明确不支持；人工建议仍可记录 |
| 有建议但无合法片段 | 无可用候选，不输出空脚本伪装完成 |

## 11. 导出范围

第一批：可读表格页面、Markdown、CSV，加原始结构化脚本 JSON。CSV 正确处理逗号、引号、换行和公式注入风险；JSON 不包含服务器本地路径或密钥。

第二批：可靠对齐字幕 SRT 与明确受支持的 Plan 执行投影。

不在首版承诺 Premiere/剪映工程文件、EDL/FCPXML 导入。毫秒显示不是 NLE 的帧 timecode；后续接入需处理实际 fps、媒体时间基准、轨道和格式限制，单独验证。

人工交付包关联源素材名称/hash，并说明需配套原素材。表格、CSV、字幕、执行 Plan 同一 revision，来源相同不代表所有建议都会自动渲染。

## 12. 分阶段范围与验收

| 阶段 | 交付 | 验收 |
|---|---|---|
| S0：格式与基线 | 固定表格、字段来源、真实小素材标注；记录当前方案 | 用户能按脚本定位取材，区分事实/建议/风险；不以示例证明质量 |
| S1：最小脚本输出 | 版本化索引、受限 Decision、时间与原文映射、表格/JSON/Markdown/CSV | 无自由时间/原话，所有导出一致；粗对齐和缺视觉明确告警 |
| S2：人工闭环 | 编辑、保存 CAS、风险处理、确认和版本导出 | 修改重算；旧确认失效；晚到回调不覆盖；稳定 rowId |
| S3：可选执行 | 可靠字幕、SRT、Plan 投影、任务隔离与结果对账 | 同版同区间，操作白名单；人工包装未被标成已执行；旧下载不覆盖 |

业务脚本最小闭环为 S0+S1+S2。自动渲染不是脚本可用的唯一验收；若进入 S3，不能只凭进程成功判定效果。前序 P0/P1/P2 与本节职责对应，不是并行启动另一套任务系统。

测试建议：

1. 示例 6 行累计为 60000ms；删除第二行后后续重算为 50000ms，原素材时间不变。
2. 一个句子跨场景、多个相邻单元合并、非连续源单元必须分行；保留原序与全文引用。
3. 29.97/25 fps、变帧率、毫秒切点的显示与映射，不以固定 30 fps 校验。
4. 粗 ASR 块包含多句不能自动细切；原话错配、缺字、字幕跨行、视觉缺失。
5. 用户改标题不改原声；接受人工包装不变成执行指令；独立字卡延时要重算且首版自动执行拒绝。
6. 每个导出同 hash/revision，CSV 特殊字符安全；稳定 rowId 与镜号重编号。
7. 修复后全量校验；旧 revision/索引拒绝；终态迟到进度、并发保存和晚回调。

真实效果测量：定位正确率与用时、脚本理解成本、人工修改次数/时间、关键内容误删/原意改变、成本与失败降级。规则、单 Agent、当前多 Agent 在相同素材和要求下对照，不用模型自评分代替人工效果。

## 13. 面试与成果边界

业务问题：分析结果难以直接指导剪辑，创作者仍要重新定位和组织素材。  
设计取舍：结构化脚本为事实来源，模型选片段和说明意图，程序映射时间与原话，表格和执行方案共用版本。  
异常边界：不把粗时间冒充句级精度，不把包装建议冒充执行，不把规则通过冒充原意保持。  
验证结果：实施后填写真实定位/修正成本、对照条件和残余失败。

当前只能表述“已确定脚本交付形式并完成设计”；版本化引用、脚本导出、人工确认等实现并验证后才可作为简历成果。
