## 1. 总体结论

最终采用“两段百度实习 + 两个个人项目”的结构：

| 经历 | 对外定位 | 主要证明什么 |
|---|---|---|
| 百度财务研发实习 | 企业财务数字化场景下的 AI 与后端研发 | 真实业务、并发控制、异步交互、接口治理和性能优化 |
| 百度 TPG AI 测试研发实习 | 语音识别系统测试与交付保障 | 真实 AI 工程背景、系统测试与问题定位意识 |
| AgentWrite | 可评测的个性化记忆 + 可靠长任务执行 | AI 应用工程深度，是差异化主项目 |
| AgentCut | 面向短视频创作者的多模态理解与受约束剪辑决策 | 多模态广度、模型输出可控性与业务闭环 |

核心叙事：

> 我具备 Java 后端与 AI 应用开发经验：实习中处理企业业务里的自动化、并发与性能问题，个人项目中进一步探索记忆、长任务可靠执行和多模态剪辑决策，并重视用评测验证系统行为。

“无状态、长任务可靠性、能力边界”适合作为面试中的技术总结，不必反复出现在项目背景里。简历优先回答“面向谁、解决什么问题、我做了什么、如何证明”，而不是宣布解决了整个行业的三大难题。

### 1.1 三种包装方式的取舍

| 方案 | 优点 | 问题 | 最终选择 |
|---|---|---|---|
| 证据驱动 | 真实、便于追问，量化结果与缺陷案例突出 | 需要整理证据 | 主方案 |
| 技术堆料 | 关键词多 | 难读，容易被质疑为了用技术而用技术 | 仅保留必要关键词 |
| 宏大叙事 | 开场有记忆点 | 容易扩大责任和效果边界 | 仅用于自我介绍总结 |

包装原则：业务上位定位可以扩大，真实项目身份与个人贡献不能替换；计划不能当成果，机制不能当效果。

### 3.2 推荐核心工作参考稿

以下基于你提供的成果，正式投递前需核对量化口径与实现边界。

1. **AI 文档处理闭环**：构建税务 PDF 解析 Agent，通过 Skill 生成结构化候选，结合后端确定性校验与可追溯入库；采用 Token 型 Redis 锁及 Lua 校验释放，防止并发重复处理与锁误删。
2. **业务自动化与异步交互**：优化 WebRPA 申报验证码交互，以 Redis 短期状态连接 RPA 回调与前端输入，将约 100 秒的同步阻塞请求改为异步短请求；结合如流通知与截图回溯支持失败触达和异常定位。
3. **第三方接口治理**：针对 DATAGO 限频约束，以 Redis 跨实例节流控制约 120ms 请求间隔，结合串行请求调度与非限频 IO 并行，将接入耗时由分钟级降至秒级；采用 1h 缓存与单飞机制抑制重复回源。
4. **聚合查询优化**：通过整页批量查询、跨群组去重、缓存及 CompletableFuture 并发回源，将人员检索接口耗时由约 3s 降至 350ms。

第三点必须能解释哪些调用串行、哪些 IO 并行。若外部接口全局要求每次调用至少间隔 100ms，并行不能突破该约束；耗时改善需来自消除不必要串行、批量化、缓存或其他明确机制。

“毫秒级短请求”只有在有实测时才补入第二点，否则保留“取消约 100 秒同步阻塞”已经足够有说服力。

### 3.3 资金项目最终怎么放

TMS 的整体业务是企业财资管理，包含账户、资金调拨、投资融资、流水回单、银企对账与财务系统协同。整体业务背景可以介绍，个人贡献只能写实际参与部分。

| 参与程度 | 写法 |
|---|---|
| 少量余额、筛选、导出需求 | 合并进实习背景或口头介绍 |
| 实质完成电子回单下载优化 | 作为候选核心点，视证据强度替换现有点 |
| 没有负责资金调拨或对账核心链路 | 不写支付清结算、资金调度算法或对账引擎研发 |

下载优化的条件式文案：

> 优化资金平台电子回单批量下载，基于线程池与 CompletionService 实现并发下载及按完成顺序打包，增加批量上限与失败处理，减少串行 IO 等待。

仅在确认由你实质参与后使用；没有性能对比，不加提升倍数。不能直接声称连接池优化已完成，也不能把 ByteArrayOutputStream 累积 ZIP 描述成恒定内存的端到端流式传输。

通投版中，已有 DATAGO 与人员查询的量化结果更强，下载优化不默认追加为第五点。它的价值是备用面试案例，不是凑模块数量。

### 3.4 技术措辞与数字校准

| 原表达或风险 | 推荐口径 |
|---|---|
| 单飞锁防穿透 | 单飞机制抑制并发重复回源，主要应对缓存击穿或回源风暴 |
| 100s → 毫秒级 | 接口阻塞/响应时间下降，不是 RPA 任务总耗时变成毫秒 |
| 120ms 间隔锁 | 跨实例节流；说明锁与时间间隔的具体实现 |
| 3s → 350ms 慢查询优化 | 若包含外部调用与聚合，写接口耗时优化，不等同于单条 SQL 优化 |
| Token + Lua 保证绝对可靠 | 防止旧持有者误删新锁；不自动解决租约过期后的并发执行 |
| 总计节省 107 人天/年 | 说明是团队口径还是个人成果，以及年化测算依据 |
| TaxHub 与 TMS 共用技术栈 | TaxHub 为 Java 21/Spring Boot 3.3；TMS 为 Java 8/Spring 4.x，应区分 |

推荐正文优先保留清楚的接口性能结果。若 107 人天是团队整体项目收益，可以写“平台按业务量测算年化节省约……”，不写成个人独立实现且已经全年观测的收益。

## 5. AgentWrite：从功能清单变成工程深度

### 5.1 推荐定位与参考稿

> AgentWrite | AI 多智能体个性化创作工作台 | 个人项目

背景：

> 面向技术创作者构建 AI 写作工作台，重点实现跨会话个性化记忆、长耗时任务可靠执行与生成内容约束。

核心工作：

1. **个性化记忆与评测闭环**：实现记忆抽取、去重、混合检索与上下文注入，融合 Qdrant、BM25 和 Reranker；独立搭建评测平台，通过预算探针识别注入与检索指标重复，并以配置指纹及 mutation 测试验证配置透传与关键守卫。
2. **长任务可靠执行**：基于 RocketMQ 解耦任务提交与 Agent 执行，采用 Transactional Outbox 将任务与事件纳入本地事务；结合任务抢占、状态流转、心跳与恢复处理重复消费和执行中断。
3. **多 Agent 编排**：基于 Google ADK 构建 Planner-Generator-Enforcer 链路，配置化管理模型、Prompt、工具与工作流，并通过规则校验约束文章格式。

技术栈可用：Java 17 / Spring Boot 3 / Google ADK / Qdrant / RocketMQ / Redis / MySQL。Python/FastAPI 在评测平台正文中体现，React 仅在空间允许时列出。

不要将项目标题改成“企业级通用 Agent 基础设施”，也不要将配置化等同于建设了通用框架生态。

### 5.2 评测平台怎样讲得有含金量

开场：

> 我不仅实现了记忆链路，还搭建独立评测平台，因为模型抽取和检索可能静默退化；重点是让比较条件可追踪、评测结果可解释，并确认测试真的能抓住缺陷。

主案例：默认预算不吃紧时，注入的无关率与检索的 1-Precision@K 重复。通过降低注入预算让二者分叉，识别原指标缺少独立信息的条件。

注意：这不说明所有注入指标都没有价值，也不说明仅靠这个探针已经验证完整的生成效果。结论只针对当时指标定义与测试条件。

备用案例：指纹预览漏传 case_limit，导致历史结果查询混淆不同样本规模；通过修复透传和故障注入测试锁住回归。

严谨口径：

- 配置指纹帮助标识比较条件，不保证相同配置下模型输出逐位一致。
- 跨参数方案比较，应固定数据集、评价口径与其他变量，并记录被改变的因素；不能说只有相同指纹的 run 才能比较。
- mutation 测试证明指定缺陷可以被测试捕获，不证明整个评测平台绝对可信。
- freeze 跳过精排时得到的是基础检索结果，不能拿它代表线上完整精排链路。
- 五维度是分层测量，不是五个独立且必然有效的质量分数；没有对应用例应显示未评测，而不是零分。

### 5.3 后端追问边界

- Outbox 解决本地数据库任务与事件的一致写入，配合投递重试达成最终交付，不是天然端到端 exactly-once。
- 任务抢占降低并发重复执行，但执行中断后重试仍需考虑外部工具副作用。
- 心跳过期代表疑似失联，不等同于原 worker 已停止；需解释旧执行者晚到结果如何处理。
- DDD 可在架构追问中展开，不作为第四个重复亮点。能解释领域对象、依赖方向和边界价值即可。

## 6. AgentCut：业务包装与现状边界

### 6.1 最终业务定位

保留短视频创作目标，不为了简历改成课程整理或企业培训产品。

推荐名称：

> AgentCut | AI 短视频智能剪辑平台

推荐背景：

> 面向短视频创作者，针对人工浏览素材、筛选片段与组织内容的成本，构建多模态视频理解与多 Agent 剪辑决策链路，辅助完成从原始素材到短视频剪辑方案的生成。

“辅助”不是弱化项目，而是准确划定模型负责建议、用户保留判断权的产品边界。

### 6.2 现阶段参考稿

1. **多模态素材理解**：融合 VLM、FunASR、VAD 与场景检测，通过动态抽帧提取带时间戳的章节、关键句与冗余片段，为短视频选材提供结构化依据。
2. **剪辑决策与可控性**：构建分析、导演与质检协作链路，通过五维评分迭代剪辑脚本，结合 12 条确定性校验与关键场景恢复兜底，降低时间区间错误和关键内容误删风险。

这是依据现有文档与部分代码的参考表达，不是本次端到端验证结论。技术栈可突出 Python / FastAPI / LangGraph / VLM / FunASR / PySceneDetect。

若空间允许，Java 17 / Spring Boot 可在项目技术栈中简要体现。仓库包含 Java 后端、Python AI 服务与 React 前端，不应在面试中把它描述为只有一个 Python 脚本。

### 6.3 本次核对到的边界

| 能力 | 依据与边界 |
|---|---|
| 方案文档作为统一契约 | README 说明生成、编辑、执行、版本存档共用方案；应验证三端是否一致遵守 |
| LangGraph | analysis_agent.py 中用于分析流水线；不直接表述为三 Agent 全部运行在持久化图工作流中 |
| 导演与质检迭代 | plan_agent.py 存在最多 3 次生成/质检循环及最高分候选选择 |
| 12 条校验 | validator.py 对区间、字幕、裁剪、引用、时长等进行检查；部分规则仅发 warning |
| 内容完整性 | 当前关键句覆盖检查是启发式 warning，不是完整语义保真保证 |
| 必须保留与删减预算 | 部分在 Prompt 中表达；写进 Prompt 不等于程序强制执行 |
| 数据持久化 | README 同时说明默认内存模式与 MySQL profile；不能仅因有数据库代码就宣称运行中全部可恢复 |
| 自动成片 | 有渲染链路，但质量暂不理想；不承诺一键高质量生成 |

目前筛选最高模型分的候选，再做校验，与“从全部硬约束合格候选中选最优”不是完全相同的机制。这是有价值的深化方向。

现有固定“保留源内容 60%～80%”的 Prompt 指引，与“从长素材提炼 60 秒短视频”的目标可能冲突。需要区分轻度精剪和主题提炼，不能将同一删除预算策略应用到所有任务。

## 7. AgentCut 下一步怎么深化

本节均为待开发或待核验方案。第一阶段建议聚焦单段语音主导素材，如口播或访谈。这是推荐切口，不是改成知识视频，也不是声称用户已经确认全部产品约束。

### 7.1 产品契约先于 Agent 扩展

输入建议：

- 单段视频与明确素材范围。
- 目标主题，可为空；为空时生成候选主题供用户选择。
- 目标时长、允许误差或“最多”约束。
- 模式：轻度精剪 / 主题提炼。
- 必须保留、禁止使用及人工锁定片段。
- 输出比例、字幕开关；风格先只做少量可解释选项。

输出建议：

- 2～3 个候选方案作为初始产品设置，实际数量再依据成本评估调整。
- 每个方案的主题、选择理由、预估时长与风险项。
- 可追溯的片段引用与版本化剪辑方案。
- 可编辑预览和明确的降级状态。

轻度精剪侧重去停顿与重复，主题提炼允许从长素材中选取较少片段。两者的关键内容定义、删减预算和质量标准应分别设置。

不承诺爆款、完播率提升、版权自动判断、多素材复杂叙事或任意题材通用剪辑。

### 7.2 五阶段闭环

```text
理解素材 -> 发现候选 -> 组织内容 -> 校验方案 -> 人工确认
```

| 阶段 | 产物 | 核心设计 |
|---|---|---|
| 理解素材 | 素材索引与质量标记 | ASR、场景、关键帧、说话人可选、统一时间基准 |
| 发现候选 | 有主题的候选片段组 | 相关性、完整性、上下文依赖、估计时长 |
| 组织内容 | 结构化剪辑方案 | 源片段引用、输出顺序、删减理由、约束版本 |
| 校验方案 | 错误与风险报告 | 程序硬校验 + 模型软评审 |
| 人工确认 | 审核后的方案版本 | 锁定片段、局部修改、比较与回滚 |

首版默认保持原素材顺序，以降低断章取义风险。重排镜头应作为显式功能，而非模型自行决定的隐式行为。

### 7.3 素材索引：让模型选择证据，不编造时间

建议为素材单元建立：

| 字段 | 用途 |
|---|---|
| asset_id、segment_id、index_version | 稳定身份与索引版本 |
| start_ms、end_ms | 源时间区间，统一整数单位 |
| transcript、scene_id | 内容与场景关联 |
| boundary_quality | 切点是否接近完整句子或自然停顿 |
| context_dependencies | 代词、定义或铺垫依赖 |
| source_quality_flags | 噪声、低质量转写、视觉缺失等标记 |

模型输出 segment_id 与选择理由，程序校验引用并映射到时间区间。必要的边界调整只能在受控邻域中完成，并重新校验。

片段 ID 不会自动解决语义错误：若索引本身切碎句子，模型选合法 ID 仍可能生成坏方案。

VAD 不等于语义分句，场景切换也不等于句子结束。需要结合转写、停顿与视觉边界，记录无法可靠对齐的情况。

变帧率视频不能仅靠“帧数/固定 fps”估算全部时间；时间基准、字幕与渲染需对齐实际媒体时间戳。

### 7.4 上下文依赖与原意保护

典型失败：

- 仅保留“所以我不建议这样做”，但删掉“这样做”的具体对象。
- 只保留结论，删除条件与限定词，改变原意。
- 把反例剪成作者主张。
- 多说话人交替时剪掉问题，留下无法理解的回答。

建议将依赖分成明确依赖与疑似依赖；前者补入前文或拒绝候选，后者作为风险供用户复核。

人工指定“必须保留”应由代码强制验证；模型推断“重要”不能直接等同于用户硬约束。主题提炼也不需要保留原素材所有高分关键句，否则无法缩短长视频。

### 7.5 硬软约束与冲突处理

推荐顺序：执行合法性与安全 > 人工锁定 > 已确认必保内容 > 语义完整性目标 > 目标时长偏好 > 节奏偏好。

若用户设置严格时长上限，同时必保内容已超过上限，应返回不可行并给出选择，而不是悄悄违反任何一个硬约束。

| 冲突 | 推荐行为 |
|---|---|
| 30 秒上限，必保内容已有 45 秒 | 要求调整时长或必保内容 |
| 禁止删除与禁止使用指向同一片段 | 输入阶段拒绝矛盾约束 |
| 修复上下文后超时长 | 重规划其他非锁定片段；无解则说明 |
| 目标主题不存在 | 返回没有匹配素材，不编造候选 |
| 用户锁定后再次生成 | 只修改允许变更部分，绑定基础方案版本 |

任何修复后必须重新检查所有约束，避免“恢复关键场景”解决内容问题却制造时长超限。

### 7.6 决策稳定性

推荐将流程调整为：

```text
生成候选 -> 硬校验 -> 可修复则修复并重校验
         -> 合格候选进入软评审 -> 保存历史候选
         -> 有预算则局部重写 -> 选最佳合格方案
         -> 无合格方案则明确失败或返回标记后的保守方案
```

要点：

- 保留当前有限迭代思想，增加总时间、Token 与模型调用预算。
- 模型高分不能覆盖硬校验失败。
- QA 报告绑定同一候选 ID，不能使用另一轮的质量报告修复当前方案。
- 修复优先做局部、可解释的动作，语义不明确时不盲目恢复整段。
- 记录正常生成、修复、降级、人工确认后的不同来源。
- 同配置输出不必完全一致，但违反硬约束的比例必须被跟踪。

### 7.7 工程稳定性与恢复

优先复用现有 Java 后端与任务模型，不为简历再造第二套重复任务框架。

先核验当前持久化与回调，再决定扩展：

| 问题 | 建议机制 | 验证场景 |
|---|---|---|
| 重复提交 | 请求幂等键与输入摘要，区别新需求和重复请求 | 同请求并发提交 |
| Worker 重启 | 持久化阶段产物与受控恢复 | ASR 完成后进程终止 |
| 重复或晚到回调 | attempt_id、状态条件更新、输入版本绑定 | 旧任务完成后回调 |
| 无限等待 | 外部调用超时、总预算、有限重试 | VLM 长时间无响应 |
| 取消与完成竞争 | 状态比较更新，禁止取消后发布结果 | 用户取消同时收到回调 |
| GPU/IO 资源紧张 | 队列与并发限额、背压 | 多视频同时上传 |
| SSE 断连 | 任务查询为权威状态，SSE 仅用于通知 | 断连后重新打开页面 |
| 局部结果缺失 | 阶段完整性校验，不发布假成功 | 索引存在但转写产物损坏 |

缓存按素材摘要、模型/索引版本与参数建立身份，不能只按文件名复用。用户锁定与方案版本也需要绑定，否则晚到结果可能覆盖人工编辑。

LangGraph 图编排不自动等于持久化恢复；检查点、存储与外部副作用边界需要单独设计和验证。

### 7.8 降级与安全

| 场景 | 策略 |
|---|---|
| VLM 失败，口播语音可靠 | 可降级为语音分析，明确缺少视觉依据 |
| ASR 质量差 | 提示低置信风险，允许用户修正转写；不发布高可信结论 |
| 无语音、音乐主导素材 | 首版超出范围时明确不支持 |
| 文件损坏或编码不支持 | 预检查失败，避免付费模型调用后才发现 |
| 全部候选失败 | 不用空脚本伪装成功 |
| 模型输出非法结构 | 严格 Schema 验证、有限修复；不直接执行 |

安全边界：素材文本和字幕属于不可信输入，不能让其中的指令改变工具权限；模型仅输出受限操作集合，不生成任意 Shell/FFmpeg 命令。执行侧还需校验文件路径、URL 来源、文件大小和资源预算。

视频可能包含人脸、声音和商业信息。外发模型前明确用户授权与保存期限，支持删除临时文件；个人 Demo 同样不要泄露真实企业素材。

## 8. AgentCut 怎么证明效果

### 8.1 三层指标

| 层次 | 核心问题 | 指标建议 |
|---|---|---|
| 工程执行 | 能否完成合法任务 | 完成率、硬约束违反率、渲染可执行率、超时与恢复结果 |
| 内容决策 | 选得是否合理 | 必保内容遗漏、上下文缺失、原意改变、重复残留 |
| 用户收益 | 是否减少工作 | 浏览定位时间、修正时间、修改次数、最终方案采用情况 |

五维模型评分只是辅助信号，不能替代这三层验证。脚本通过校验也不能直接证明成片节奏、字幕观感或构图良好。

### 8.2 小规模评测设计

建议先准备 20～30 条可授权素材，覆盖口播、访谈、低音质、长停顿、重复观点、代词依赖和无匹配主题；这是起步建议，不是已有测试数量。

每条定义任务意图、时长条件、必保内容、禁止内容、允许切点与已知风险。剪辑可以有多种合理答案，不要求唯一正确片段列表；应评价约束与信息表达，而不是仅与一个参考方案做精确匹配。

基线：

1. 简单规则：去停顿或关键词选段。
2. 单模型/单 Agent：一次生成剪辑方案。
3. 多 Agent：分析、导演、质检与约束组合。

分别比较 ASR-only 与 ASR+VLM、有无质检、有无上下文依赖检查。固定数据与评价口径，同时报告调用成本、耗时和质量，避免仅报告最高分。

重复运行观察波动，保留失败样本；调参样本与最终验证样本分开。人工评审隐藏方案来源，条件允许时由第二位评审复核分歧；只有自己评价时如实说明局限。

模拟模式用于接口冒烟，不能用于真实多模态效果、性能与业务收益结论。

### 8.3 真实失败案例的价值

现有导演设计文档记录过：一次优化后视频更短，但 QA 内容完整性更差，出现铺垫缺失与拆断句子。

这个案例可以证明你识别了“更短不等于更好”的指标冲突，不可以当作优化成功证据。后续应形成：

> 失败样本 -> 定位信息传递或约束问题 -> 修改机制 -> 相同任务重复验证 -> 报告收益与残余失败。

本次未复跑该素材，因此不承诺修复已达到某个评分。

## 9. AgentCut 面试问题与回答框架

| 问题 | 回答重点 |
|---|---|
| 业务价值是什么？ | 降低素材浏览、选材与组织成本，辅助剪辑决策；收益需实测 |
| 为什么不是简单去停顿？ | 去停顿处理节奏，不处理主题选择与上下文完整性 |
| 为什么要 VLM？ | 表情、动作、屏幕内容不能仅由 ASR 获取；口播场景通过消融判断增益 |
| 为什么多 Agent？ | 职责分离方便追踪和重试，但价值须与单 Agent 在质量/成本上比较 |
| QA 也会幻觉怎么办？ | 模型软评审、代码硬校验、人工确认分工，不宣称 QA 保证语义正确 |
| 怎样避免时间戳幻觉？ | 素材 ID 映射与执行侧校验；未来机制与现有实现分开回答 |
| 怎么避免断章取义？ | 上下文依赖、条件与否定保留、首版顺序限制、人工复核 |
| 为什么不一直重写？ | 总预算与有限轮数，保留合格候选，避免成本失控与越改越差 |
| 12 条规则通过就好吗？ | 只能覆盖声明的执行约束，内容审美与原意仍需评测 |
| 目标时长与必保冲突怎么办？ | 显式不可行，用户调整约束，不偷偷删内容 |
| LangGraph 能自动恢复吗？ | 编排与持久化检查点不同，恢复还涉及产物、版本与副作用 |
| 成片质量如何？ | 目前仍在优化，主要贡献在素材分析与脚本决策，有失败定位但不夸大效果 |

推荐项目开场：

> AgentCut 面向短视频创作者，核心是先理解素材，再生成可校验的剪辑决策。模型负责内容分析与方案建议，程序负责执行边界，用户保留修改权。当前已实现多模态分析、质检迭代与规则兜底，自动成片质量仍在优化；我希望下一步重点验证选材收益与关键内容保护，而不是继续堆 Agent。

未来能力尚未完成时，回答“我准备这样设计，因为……”；不要回答“系统已经这样保证”。

## 10. 深化优先级与简历更新条件

### 10.1 分阶段建议

| 阶段 | 优先事项 | 完成证据 |
|---|---|---|
| P0：整理事实 | 核实个人贡献、日期、性能数字、真实与模拟运行模式 | 贡献清单与可展示证据 |

| P3：完善可靠闭环 | 阶段恢复、幂等回调、取消、人工锁定与版本保护 | 故障注入与恢复记录 |
| P4：优化成片体验 | 字幕、画幅、切点、音画同步 | 人工观感与修正成本验证 |

P1 与 P2 可小步交替，但不要没有基线就大改全链路。秋招优先把已有项目讲清楚，AgentCut 扩展不应挤占 Java 基础与实习案例准备。

| 人工可控生成 | 锁定、局部重规划、版本冲突与回滚测试 |
| 阶段恢复 | 重启后复用已完成产物、拒绝晚到结果 |
| 降低关键内容误删 | 统一口径的对比测试，不只一条视频 |
| 减少人工剪辑时间 | 相同任务与质量要求下的人工计时记录 |
| 多 Agent 优于单 Agent | 质量、成本、耗时联合比较及残余失败 |
