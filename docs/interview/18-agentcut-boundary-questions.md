# AgentCut 边界问题清单

日期：2026-10-17

用途：供后续需求分析与设计评审使用。本文只提出问题，不给解决方案，不认定问题已发生或已有机制能够处理，不构成实施授权。

关联范围：单页任务工作台、视频分析生成时间轴脚本、包装素材库及后续渲染导出。

## 1. 视频上传

1. 网络中断、刷新页面或浏览器关闭后，已上传部分是否保留？
2. 大视频上传到一半失败，用户是否需要从头上传？
3. 用户重复点击上传，同一个视频会不会生成多份文件和记录？
4. 上传成功但元数据保存失败，或者记录保存成功但文件不完整，会怎样？
5. 多人同时上传大文件，会不会耗尽内存、磁盘或连接数？
6. 文件扩展名正确但内容损坏、格式不支持，什么时候发现？
7. 视频尚未上传完整，是否可能被提交给 Agent 分析？

## 2. 分析稳定性

1. ASR、VLM、导演或质检某一步失败，整个任务是否必须重新开始？
2. 部分音频转写失败，系统会不会仍把不完整报告标成成功？
3. 单次模型调用长时间无响应，任务什么时候停止等待？
4. 任务还有心跳，但某个阶段一直没有实际进展，如何识别？
5. Python 服务或 Java 服务重启后，运行中的任务会处于什么状态？
6. 真实分析失败后，是否可能进入模拟路径并被用户误认为真实结果？
7. 同一视频重复分析，结果差异多大才算可接受？

## 3. 并发与资源

1. 多人同时提交分析任务，最多允许多少任务实际运行？
2. 排队任务是否有数量上限、等待期限和用户可见状态？
3. ASR、视频解码和 VLM 分别受 CPU、GPU、内存还是模型限流约束？
4. 长视频是否会长时间占用资源，让短视频任务一直等待？
5. 同一用户连续提交大量任务，是否影响其他用户？
6. 模型出现限流后，多个任务同时重试会不会进一步放大压力？
7. 分析、素材入库和渲染同时执行时，会不会互相争抢资源？

## 4. 任务提交与回调

1. Java 提交超时，但 Python 已经受理，用户重试会不会重复执行？
2. Python 已完成，但完成回调丢失，任务会不会一直显示运行中？
3. 回调重复、乱序或晚到，会不会重复保存脚本或复活失败任务？
4. 旧分析结果晚到，会不会覆盖用户已经修改的新脚本？
5. 用户重试、取消和任务完成同时发生时，最终状态是什么？
6. 前端断网或切换任务后，旧响应会不会显示到另一个任务里？

## 5. 脚本与内容正确性

1. ASR 时间只有块级精度时，脚本是否会给出不可信的句级切点？
2. 删掉定义、条件、否定或问句后，剩余内容是否改变原意？
3. 时长上限与必要上下文冲突时，系统会如何表达结果？
4. 修复后的方案是否可能产生新的重叠、字幕错误或时长违规？
5. 规则通过但语义有问题，是否仍能被标成可确认？
6. 用户修改原文、片段或边界后，原来的质检结果是否仍然有效？

## 6. 素材库与包装

1. 素材授权到期、下架或文件丢失后，历史脚本是否还能使用？
2. 表情或示意动画是否可能暗示嘲讽、改变立场或被误认为事实画面？
3. 素材太短、没有透明通道或无法循环时，推荐是否仍可落实？
4. 包装是否遮挡人物、字幕或重要演示内容？
5. 没有合适素材时，Agent 会不会为了完成任务而强行插入？

## 7. 渲染与导出

1. 用户点击导出后继续编辑，最终渲染的是哪个版本？
2. 多个渲染任务同时执行，临时文件和输出是否会互相覆盖？
3. 渲染超时、磁盘不足或进程崩溃后，是否留下半成品？
4. 进程执行成功，但视频黑屏、无声或字幕错位，是否算成功？
5. 未支持的包装操作是否会被静默忽略？
6. 历史下载链接是否会失效，或下载到后来覆盖的新文件？

## 8. 安全与成本

1. 用户是否能通过素材 ID、预览或下载接口访问其他人的视频？
2. 视频中的字幕、OCR 或口播是否可能诱导 Agent 执行非预期指令？
3. 单个任务最多消耗多少时间、模型调用和费用？
4. 重试、降级和重复执行产生的成本，是否有记录？
5. 视频、转写和临时文件保留多久，删除后是否仍有副本？

## 9. 首轮优先讨论的问题

围绕“先跑通真实视频分析生成脚本”，优先讨论：

1. 上传完成与文件完整性如何界定？
2. 分析失败、部分成功和降级的边界如何界定？
3. 分析并发容量与资源耗尽的边界在哪里？
4. 提交不确定、重复及晚到回调会带来哪些状态和结果冲突？
5. 脚本的时间、原文与语义可信度如何界定？
