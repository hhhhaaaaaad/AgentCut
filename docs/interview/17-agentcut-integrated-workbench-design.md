## 1. 设计结论与需求对应

### 1.1 推荐结论

采用“单页任务工作台 + 结构化脚本事实来源 + 可选包装素材推荐”的渐进设计。

完整业务链路：

> 选择主视频 → 创建任务 → 理解视频 → 发现主题候选 → 组织脚本 → 校验与质检 → 人工修改/确认 → 可选库素材包装 → 确认可执行快照 → 渲染 → 预览/下载。

当前优先级：

> **先跑通真实视频分析到剪辑脚本，不先做全功能素材库，不先重建渲染引擎。**

一个页面集中任务创建、执行进度、脚本结果和视频导出；后台分析、脚本保存和渲染仍保持职责分离。“一个页面”不等于一个巨大组件或一个贯穿所有步骤的同步 HTTP 请求。

### 1.2 四项新需求

| 用户需求 | 综合设计 | 实施顺序 |
|---|---|---|
| 展示已有素材，支持上传及复用视频/图片/动画 | 素材中心分主视频、包装素材两类；系统授权库与个人库分组 | 首阶段只需上传/选择主视频，完整库后续 |
| 展示已创建任务列表 | 服务端查询，全局筛选、项目过滤、最近更新时间；点击恢复任务工作区 | 首阶段提供基础列表 |
| 创建、状态、成片尽量同页 | 任务列表 + 当前任务工作区，按阶段切换内容，素材详情用抽屉 | 首阶段搭骨架，渲染后续接入 |
| 先跑通 AI 分析生成脚本 | 独立验收主链路，不依赖素材推荐、动画合成或长任务恢复 | 第一优先 |

### 1.3 与此前设计的关系

- 延续 15 号文档的七列脚本、版本化索引、事实与建议分离。
- 延续 16 号文档的合法库素材 ID、候选比较、NONE、叠加/覆盖优先。
- 最新优先级覆盖此前“先完整人工闭环再交付”的顺序：第一阶段先完成真实分析与脚本可查看/导出；编辑 CAS、确认与包装在后续阶段扩展。
- 第一阶段能演示脚本生成，不等于已具备完整编辑确认、可靠恢复或自动成片能力。
- 本文为综合评审入口，15/16 号文档保留，具体机制可查原文，不覆盖其已有内容。

## 2. 产品边界与替代方案

### 2.1 业务边界

第一业务任务：从一段语音主导素材中提炼一个主题，保留原声及必要上下文，形成可编辑短视频方案。

建议实验范围为 2～10 分钟主视频，成片上限 30/60/90 秒；只是实验配置，不是性能承诺。访谈可有多个说话人，但不承诺自动说话人识别；问答依赖不清时需保留问句或人工检查。

默认原序、原速、硬切。图片/动画作为辅助包装，不作为第一阶段的主分析输入。静态图片可展示一段时间，但不因此成为“有语音的主视频”。

不做复杂多素材叙事、任意生成口播、自动爆款、一键高质量成片；不虚构商业客户或上线规模。

### 2.2 可选产品路线

| 路线 | 优点 | 问题 |
|---|---|---|
| 保留上传/分析/编辑/渲染分离页面 | 最少布局变化 | 操作来回跳转，任务与结果关联弱 |
| 全部能力一次重写成专业时间线编辑器 | 可视化完整 | 工期大，先解决前端与轨道问题，无法尽快验证 AI |
| **任务工作台逐步扩展，推荐** | 主链路先验证，复用后端与组件，仍能集中操作 | 要区分阶段状态、资源身份和版本 |

不为本项目补齐框架数量：前端沿用 React/Zustand/Ant Design，Java 沿用现有分层，Python 保留现有 Agent；先轮询，不默认加 SSE、MQ、向量库或新任务系统。

## 4. 单页工作台设计

### 4.1 信息组织

“剪辑工作台”是一个路由，可用查询参数保存选中的 projectId/taskId；刷新通过服务端重新加载，不依赖浏览器内存。

页面区域职责：

| 区域 | 内容 | 操作 |
|---|---|---|
| 任务导航区 | 已创建任务、筛选、状态、创建时间/阶段 | 新建、选择、重试入口、查看历史 |
| 当前任务摘要 | 主视频、主题、时长约束、当前阶段、版本 | 查看参数/源素材，后续重新分析 |
| 主工作区 | 新建表单、进度、脚本、结果按任务状态展示 | 同页创建、查看、修改、导出 |
| 素材入口 | 主素材选择、已有个人/系统库、上传、筛选 | 抽屉选择与预览，不中断工作 |
| 详情区 | 原视频播放、原文、风险、素材建议、日志 | 定位时间、确认内容、查看失败原因 |

这只是信息结构，不锁定具体像素布局或设计风格。窄屏任务列表可收为抽屉，脚本表可横向滚动，不能因适配隐藏原区间和风险。

### 4.2 用户流程

1. 打开工作台，看到自己的历史任务。
2. 点击新建，上传主视频或选已有可分析视频。
3. 填任务名称、目标主题、时长上限，选择是否需要字幕；默认原序原速。
4. 创建后列表立即出现任务，主区展示阶段和进度。
5. 完成后原位置展示七列脚本与风险，不跳另一页面。
6. 点击脚本原区间，源视频定位播放；展开原文和判断依据。
7. 首阶段可导出草稿；后续可修改、保存、确认和添加包装。
8. 渲染能力接入后同页创建渲染任务，展示进度、实际结果与下载。

### 4.3 任务列表

列表显示任务名、主素材缩略图/名称、类型、状态、阶段、创建/更新时间、结果摘要。按更新时间与 ID 稳定排序，分页，筛选状态/项目/类型。

第一阶段列表保留执行任务语义：ANALYZE、RENDER 是独立任务，渲染项关联脚本与生成任务；未来可按项目分组，不能把渲染失败改写成分析失败。

默认任务列表以当前用户可见任务为范围。若现有身份认证不足，首阶段仅可信单用户本地演示，不能用客户端填写 userId 实现权限；公开/多用户部署前必须服务端身份与资源鉴权。

### 4.4 页面状态与交互细节

- 新建表单未提交不产生运行任务，浏览器关闭不视为任务取消。
- 重复点击禁用只是交互保护，服务端 requestId 幂等才是结果保护。
- 选其他任务时仍允许原任务后台运行；页面请求携带 taskId，旧响应不能写入新任务视图。
- 未保存修改离开任务时提示处理；不静默覆盖。
- 轮询断网展示“状态暂不可获取”与最后更新时间，不把任务标 FAILED。
- 原视频预览和脚本模拟播放标明区别；没有真实渲染不得标“成片预览”。
- 第一阶段导出视频按钮不开放，只解释“本阶段支持脚本导出”；不点击后静默执行旧 apply。
- 失败显示阶段、可读原因和诊断 ID，密钥、完整本地路径不展示。

## 5. 首个 AI 脚本闭环

### 5.1 第一阶段必要项

只包含主视频上传/复用、显式输入选择、创建 ANALYZE、任务列表/详情、真实分析与导演/QA、结构化脚本、源片定位、草稿导出。

```text
前端选择 assetId + 用户意图
  → Java 校验并保存任务输入
  → Python 受理并返回 jobId
  → 真实解析/ASR/场景/视觉分析
  → 构建带精度标记的素材索引
  → 导演选择合法语义单元 ID
  → 程序映射原声和时间，校验
  → QA 查原文与上下文，有限修订
  → Java 验证并保存任务结果脚本
  → 前端同页显示与导出
```

不要求等待完整素材库、动画推荐、人工锁定、自动渲染、任务自动恢复后才能测试。

### 5.2 “跑通”定义

真实文件可读取；ASR 有实际结果；模型实际生成决策；程序输出非空脚本；Java 接收并关联任务；前端可刷新查询和定位；所有模拟/失败/降级明确标注。

脚本的素材区间与原话真实可追溯，成片时间可计算。流程终态成功不证明原意完整，但不能存在未报告的虚构时间、模拟口播或非法片段。

QA 高风险未解决可得到 NEEDS_REVIEW 草稿，仍可查看/导出带标记结果，但不计为可确认成功；必须分别报告无风险、需检查、失败。

### 5.3 输入要求

首阶段建议用户明确主题，减少“自动选题是否合适”与“剪辑是否合理”两个变量混在一起。主题为空可由系统建议并待用户选，不自动代表用户目标。

必需字段：assetId、taskName、mode=TOPIC_EXTRACT、topic、maxDurationMs、requestId；可选 style、subtitleRequested、aspectRatio。

aspectRatio 是输出偏好，脚本阶段可记录；未经构图/渲染验证不承诺已经正确竖屏裁切。subtitleRequested 无可靠对齐时返回需求未满足和原因，不制造假同步字幕。

## 6. 多模态分析与 Agent 职责

### 6.1 素材分析

- 探测 duration、音轨、尺寸、帧率/时间基准；损坏文件明确失败。
- VAD 标语音/停顿候选，ASR 给真实文本与时间精度；VAD 不是完整句子边界。
- 场景完整覆盖源视频，视觉抽帧预算独立于源区间索引，不因采样预算丢弃可选择区间。
- VLM 读取授权真实帧，提供画面证据及限制；缺视觉时可 ASR-only 降级，不编造画面。
- 索引区分声学块、句子/语义单元和场景。没有可靠细对齐时只允许粗粒度选取，必要时人工对齐。

### 6.2 受限决策

| 职责 | 输入 | 输出 |
|---|---|---|
| 分析 | 原文、视觉、时间与来源 | 主题单元、关键内容及上下文依赖建议 |
| 导演 | 用户主题、合法单元、约束 | 有序 ID、内容作用、选择理由；不输出自由区间 |
| 映射/校验程序 | 单元引用、素材索引 | 原区间、原声、成片时间、合法性与冲突 |
| 质检 | 选中原文、邻接删减内容、依赖与脚本 | 风险、定位到 rowId/unitId 的修订建议 |
| 包装推荐（后续） | 已有脚本、合法候选 | 插入/叠加建议或 NONE |

五个职责不是五个新 Agent。LangGraph 是否继续用于分析不影响契约，不把“使用图”说成持久恢复。

### 6.3 迭代与预算

沿用最多 3 轮作为起始配置。任务 deadline、调用次数和重试共享预算；单次调用受剩余预算约束。

先硬合格再入 bestCandidate 池；QA 高分不绕过规则，高原意风险不被平均分掩盖。修复/fallback 后全量校验，QA 报告绑定候选 hash，不能沿用修改前报告。

QA 不可用且有硬合格脚本时输出需复核，不假装评审通过。无合格脚本明确失败或无可用候选，不强行倍速/删必要信息满足时长。

## 7. 时间轴剪辑脚本契约

### 7.1 用户表格

**镜号｜成片时间｜原素材入点—出点｜画面｜原声／声音｜字幕与包装｜剪辑备注**

一行是连续播放的编辑片段，不等于一个检测场景。非连续源区间拆行；相邻语义单元可合并，不强拆完整句子。

虚构示例，仅演示格式：

| 镜号 | 成片时间 | 原素材入点—出点 | 画面 | 原声／声音 | 字幕与包装 | 剪辑备注 |
|---|---|---|---|---|---|---|
| 01 | 00:00–00:06 | 主视频 00:18–00:24 | 正面采访，需真实帧证据 | 原文引用：“视频不是剪得越短越好……”；展开全文 | 普通字幕待对齐；标题建议单列 | 引出主题，保留完整转折 |
| 02 | 00:06–00:20 | 主视频 01:15–01:29 | 采访举例 | 原文引用，非模型重写 | 后续可建议关系箭头动画 | 保留指代先行词及案例 |

### 7.2 内部模型

EditingScript 快照：

| 字段 | 说明 |
|---|---|
| scriptId/scriptSchemaVersion/revision | 契约版本与服务端归档版本分开 |
| projectId/generationTaskId | 归属与生成任务，不用 Python job 伪造资产 ID |
| assetRef/indexRef/inputHash | 文件与索引版本可追溯 |
| target/constraints | 用户主题、模式、时长等输入快照 |
| rows[] | rowId、sourceUnitRefs、原区间、成片区间、原声引用、视觉证据、作用与理由 |
| captionCues | 原文来源、全局输出时间、对齐质量 |
| packagingSuggestions | 人工文案及 MediaPlacement，尚无库时为空 |
| validation/quality/riskItems | 校验版本、候选 hash、未解问题及工具来源 |
| reviewStatus/scriptHash | 草稿/需复核/可确认/已确认 |

一份保存快照派生表格、JSON、Markdown、CSV和未来执行投影，不让模型分别生成互不一致的格式。现有 Plan 1.0 是执行投影，不直接额外塞入违反 schema 的字段。

### 7.3 时间计算

内部整数毫秒与真实媒体时间基准，区间左闭右开。首版原速硬切：

```text
duration(row) = sourceEndMs - sourceStartMs
outputStart(row1) = 0
outputStart(rowN) = outputEnd(rowN-1)
outputEnd(row) = outputStart(row) + duration(row)
```

时间由程序计算，前端只格式化显示，不以显示四舍五入值回写。帧/音频量化后重校验覆盖及上限，不固定 30fps。

原声逐字引用真实转写，允许展开校正但不能把摘要当原话。粗 ASR 块不按字数均摊时间；未对齐的全文显示为“块级转写”，不能直接声称字幕已同步。

### 7.4 编辑与确认（第二阶段）

选删/补回完整单元、编辑标题与备注，原区间和成片时间只读。手调边界需形成新索引单元/版本后再引用。

保存 expectedRevision，返回新 revision/hash/validation；冲突 409，不覆盖。回滚产生新当前版本，不改历史。

确认绑定 revision、脚本 hash、素材/index 版本、约束与校验版本。人工锁定后续显式字段与门禁，不能从“备注必须保留”推定锁定存在。

SCRIPT_CONFIRMED 与 executionReady 分开。需复核草稿可带水印式文本标记导出，不能直接准入渲染。

## 8. 素材中心与包装推荐

### 8.1 一个入口，两类使用目的

| 分组 | 用途 | 媒体 |
|---|---|---|
| 我的主视频 | 创建分析任务的原始内容 | 语音主导视频 |
| 系统包装库 | 预置且获授权的通用包装 | 视频、图片、动画 |
| 我的包装素材 | 用户上传并明确许可/可见范围 | 视频、静态图片、动画 |

可以共用底层媒体记录，但角色通过关系明确，不把所有上传文件都设 SOURCE。同一合法媒体可有多种用途，创建任务显式选主 assetId。

卡片展示真实缩略图、类型、尺寸、时长/静态标记、许可/可用状态；可按标签、主题、风格、媒体类型筛选。图片无天然时长，时长由放置规则指定；动画标实际周期/可用片段，不凭扩展名判断透明或可循环。

### 8.2 上传与入库

上传 → 类型/大小/解码检查 → hash及元信息 → 真实缩略图/预览 → 内容描述/标签建议 → 人工核实 → 发布。

主视频阶段只需解析和可访问；包装库发布需授权与内容适配核实，不能因上传成功就自动进入推荐池。

文件与描述版本不可变，许可/上下架实时检查。删除使用下架/逻辑删除保护引用，物理回收独立处理，已引用素材不可立即删除导致历史脚本无法追溯。

### 8.3 推荐流程

1. 导演识别包装意图，允许 NONE。
2. 先过滤用户权限、许可、模式、时长、尺寸与核实状态。
3. 小库按标签/关键词召回有限候选，例如最多 5 个。
4. Agent 比较原文、叙事作用与候选真实画面/运动/声音证据。
5. 输出合法素材版本 ID、理由、行/单元锚点、模式和受限位置建议。
6. 程序校验，用户预览确认/替换/拒绝。

不默认引入向量库或 Reranker；基线发现标签召回不足后再做检索消融。

### 8.4 四类操作

| 模式 | 时间/声音 | 顺序 |
|---|---|---|
| OVERLAY | 叠加图/动画，主时长不变，默认素材静音 | 先推荐，后单独验证渲染 |
| COVER_VIDEO | 暂时覆盖画面，主口播连续，时长不变 | 同上 |
| INSERT_GAP | 独立插入视频，增加时长，后续时间移动 | 后续 |
| TRANSITION_EFFECT | 合法效果预设，可能需重叠余量 | 后续，不与转场资产混淆 |

MediaPlacement 引用 libraryAssetId/assetVersion/segmentId，anchor=rowId+unitId/可信边界，最终时间由程序算。素材太短不擅自拉伸或循环；静态图片展示时长通过有限预设，不由天然 duration 推导。

必须明确原声保留、库音频静音、图层和字幕安全区。未知遮挡风险提示人工检查；表情与示意图不得歪曲立场或伪装事实证据。

### 8.5 与渲染衔接

PROPOSED、ACCEPTED_MANUAL、COMPILED、REJECTED 分开。接受建议不代表已合成。

未支持的包装在渲染时不静默忽略：用户可明确选择“仅导出基础口播版，不含这些包装”，系统生成新的执行快照并列未包含项；想包含全部则阻止渲染直到能力支持。

## 9. 任务、脚本、渲染状态

### 9.1 三类状态分离

| 维度 | 建议状态 | 意义 |
|---|---|---|
| 执行任务 | PENDING/RUNNING/SUCCESS/FAILED，取消后续加 CANCELLED | 该次执行是否完成 |
| 脚本审阅 | DRAFT/NEEDS_REVIEW/READY_TO_CONFIRM/CONFIRMED | 结果是否可采用 |
| 渲染任务 | 同一 Task 状态机，type=RENDER | 指定执行快照是否生成媒体 |

第一阶段不为尚未实现的取消显示按钮。SUCCESS + NEEDS_REVIEW 表示产出了需人工检查的草稿，不表示已通过内容验证。

无可用候选/输入不支持以明确 outcome/errorCode 表示，第一阶段映射 FAILED，不输出假空脚本。存在草稿的质量告警映射 SUCCESS + NEEDS_REVIEW；两者统计分开。

### 9.2 分析阶段

建议 phase：VALIDATING_INPUT、PROBING、TRANSCRIBING、VISUAL_ANALYZING、INDEXING、PLANNING、CHECKING、PERSISTING。并行 ASR/抽帧可显示子步骤，不用字符串直接决定状态机。

进度是估计而非剩余时间保证；100% 只在 Java 成功提交结果后显示。单调用很长时独立心跳，不能只在步骤变化时刷新；step 与 heartbeat 分离。

### 9.3 分析与渲染关联

一个 Project 为工作容器，一个 Task 为一次执行；重分析产生新 ANALYZE 任务，重渲染产生新 RENDER 任务。

Task 保存 relatedTaskId/scriptRevision，页面可同一工作区展示相关渲染项，但保留独立历史。首阶段每项目限制一个活跃分析，用服务端条件检查，不用浏览器按钮约束替代。

### 9.4 终态与重试

终态不被迟到进度/完成事件复活。重复回调按 taskId/runId/attempt/eventId/resultHash 去重，进度 sequence 只前进。

用户重试首阶段为新任务关联旧任务，不覆盖旧记录；技术 attempt 是同一任务的执行尝试，只有后续恢复/可靠分发支持后才自动增加，不能无限重试昂贵调用。

## 10. 后端分层与数据设计

### 10.1 分层职责

| 层 | 职责 |
|---|---|
| trigger | 工作台查询、上传、创建/查询任务、脚本保存/导出、确认/渲染接口 |
| app | 组合项目/资产/任务/脚本，短事务提交、跨服务执行请求 |
| domain | 单元引用和约束、版本冲突、任务状态推进、确认与准入规则 |
| infrastructure | 仓储、可信文件存储、Python HTTP、渲染执行器、预览/下载 |
| Python | 素材理解、索引构建、语义决策、QA、库素材比选 |

复用 Task/Asset/Plan/AnalysisReport，不同时建立第二套任务和方案系统。脚本领域结构与执行 Plan 分离，归档可复用现有 plan_version 加明确类型/契约元信息；迁移字段以实际表结构为准，不能无版本混存 JSON。

### 10.2 最小数据增量

| 记录 | 最小字段/演进 |
|---|---|
| Task | projectId、selectedAssetId、target/inputHash、requestId、phase、jobId/runId、attempt、heartbeat、结果引用、错误与时间 |
| Asset | 真实媒体类型、可信 objectKey、hash、探测状态、预览引用、归属；现有记录渐进补 |
| AnalysisReport/Index | assetHash、analysisVersion、tool provenance、原转写、完整场景、语义单元与对齐质量 |
| Script revision | revision、generationTaskId、indexRef、scriptJSON/hash、validationVersion、reviewStatus |
| Confirmation（后续） | revision/hash、约束/索引、确认者/时间、执行准入信息 |
| Library metadata（后续） | 资产版本、标签/内容证据、许可、发布状态、可用片段/模式 |
| Render result（后续） | executionSnapshotHash、输出 assetId、实测时长/大小、失败诊断 |

时间统一 UTC/带时区，前端本地化。Java Long ID 在 JSON 中统一以字符串输出，避免 JS 大整数精度问题；本轮源码可见项目/任务 ID DTO 不完全一致，需契约测试。

### 10.3 分发与保存

第一阶段可保留短时同步 HTTP 受理：Java 先建任务，HTTP 有短超时并校验 202+jobId，绑定成功后返回 taskId；不在请求中等待模型完成，不宣称已有可靠分发。

受理超时可能 Python 已执行，标 SUBMISSION_UNCERTAIN 的错误，保留任务供诊断；按同一 runId 查询/重试受理，不盲目创建新 job。Python 需受限幂等受理；内存去重只保证当前进程。

真实持久化领取、lease、阶段 checkpoint 可后续补至现有任务体系。未实现前进程重启可失败/任务超时，不能承诺自动恢复。

完成保存需短事务：检查当前 attempt/状态 → 验证输入/结果 → 保存索引/脚本引用 → 标任务终态。外部模型/媒体调用不放事务内。

每任务先保存自己的脚本结果；用户当前项目版本已变更时，结果仍可作为候选展示，不覆盖。第一阶段若禁止编辑且单活跃分析，仍需回调原子状态更新避免重复归档。

### 11.3 Python 与 Java

提交携带 taskId/projectId/assetId/assetHash/target/inputHash/runId/attempt、受控媒体引用、由服务端构造的回调地址。Python 不生成伪 assetId，不接受浏览器任意 callbackUrl。

进度事件：eventId、runId/attempt、sequence、phase、progress、heartbeatAt。完成事件：executionStatus、outcome、inputHash、resultHash、artifactRefs、error、toolProvenance。

Java 先检查 failed/success，再解析产物；Python failed 时不把空 {} 当正常 plan。结果成功也需 Schema/ID/版本/时域准入，终态前原子提交。

兼容旧回调需显式版本路由/白名单，不能长期以“event 缺失都当完成”绕过新校验。回调需身份认证和大小限制。

回调丢失时根据持久 jobId 有界查询状态并补提交，未实现前失败如实报告；Python 内存状态丢失时不能推断成功。

## 12. 存储、播放与导出

### 12.1 媒体与元数据

元数据存现有仓储；媒体和大产物存可信文件/对象存储引用，避免把视频塞数据库。

同机开发可使用本地受控目录，但浏览器使用授权 HTTP 媒体接口，不返回 file://。Java/Python 共盘时明确路径映射；跨机需受控短期下载 URL或共享存储，不把 Java 本地路径直接传远端。

支持 Range/206、正确 Content-Type、可定位播放；签名过期需重新获取，不将短期 URL 作为素材身份保存。上传先限制大小/类型，后续替换 byte[] 为流式策略，不把当前内存上传描述成低内存。

### 12.2 导出

第一阶段导出脚本 JSON/Markdown/CSV，附 revision、源 hash、索引版本、风险和未确认标记。CSV 转义引号/换行并防公式注入。原素材与许可说明可按权限关联，不自动分发受限原文件。

字幕 SRT 在对齐可靠且经过测试后加；SRT 不表达关键词高亮。脚本不是剪映/Premiere 工程文件，不承诺一键导入。

### 12.3 视频成片阶段

固定确认版本 → 编译受限执行投影 → 创建异步 RENDER → 独立 task 目录处理 → ffprobe/播放检查 → 输出资产登记 → 下载。

媒体操作白名单、参数限幅、可信源路径；模型不能输出 shell/filtergraph 或任意命令。原序原速硬切先验证，包装轨后续扩展新契约，不偷偷复用单 source schema。

每任务独立输出，历史下载不被新任务覆盖；任务准入后用户继续编辑不改变正在执行的快照。旧确认在新任务准入前失效。

执行快照显式列未支持包装；基础版导出需用户授权剔除这些建议，不等于完整包装成片。

## 13. 异常、预算和安全

| 情况 | 系统行为 | 页面表达 |
|---|---|---|
| 无主视频/多 SOURCE | 创建时显式 assetId 校验 | 要求选择，不随机 findFirst |
| 损坏/无语音/不支持输入 | 输入失败或不支持 | 说明范围，不生成模拟口播 |
| ASR 部分缺失/粗对齐 | 覆盖告警、粗粒度候选或失败 | 显示缺失/精度，不假细切 |
| VLM 失败 | 有语音则可 ASR-only | “视觉未验证” |
| 高原意风险 | NEEDS_REVIEW 草稿 | 查看风险，不能直接确认 |
| 必需上下文超过上限 | 冲突/无可用候选 | 调整目标，不强行倍速 |
| 最高分候选非法 | 不进入合格池 | 返回此前合格候选或失败 |
| QA/修复失败 | 有界降级并重新校验 | 明确质量证据缺失 |
| 受理超时 | 不确定状态，查询/幂等协调 | 显示错误和诊断，不假排队 |
| 晚到/重复回调 | 条件更新、原子提交 | 不复活、不覆盖 |
| 浏览器断网/刷新 | 重新查服务端 | 不把 UI 断开视为任务失败 |
| Python/Java 重启 | 当前无自动恢复则失败/超时 | 明确状态不可恢复边界 |
| 素材许可撤销 | 推荐/确认/导出再次检查 | 需替换，不静默更换 |
| 渲染损坏/音轨不符 | 结果检查失败 | 失败原因，脚本仍保留 |

任务输入设置文件大小/时长/分辨率、并发数、模型调用/重试/总 deadline、渲染超时。具体值用基线测试确定；无队列/领取能力时饱和返回 503，不假装已无限排队。

媒体解析限制资源、路径穿越与 SSRF防护；可信服务构造媒体/回调地址，限制重定向和下载体积。模型输入中的 OCR/原文/文件名是非可信数据，不是系统指令。

密钥仅服务端，日志不记录凭证或不必要完整私密转写；对外模型处理素材需授权。系统预置素材必须有许可记录，不抓企业/他人内部资料。

## 14. 分阶段实施建议

### M0：准备与事实基线

冻结当前代码指纹和未提交改动清单，核实实际模型/ASR/FFmpeg配置与依赖；使用自制/授权素材记录当前链路的失败和耗时。

验证 Java/Python文件可达、源视频可浏览器播放、回调可达。列出现有模拟入口，真实模式禁止隐式模拟完成。

M0 不重写项目，现有用户改动必须保留；实施前再读取实际状态，明确相关改动归属与兼容。

### M1：最高优先，真实视频到脚本

包含：主素材上传/显式复用、任务列表/详情、短受理与 jobId、输入快照、真实分析、版本化粗/细单元、导演 ID 决策、统一门禁、QA、脚本保存、七列表格、源片定位、草稿导出。

暂不包含：完整素材库、包装推荐、专业时间线、人工锁定、确认渲染、自动恢复、取消、多节点扩容。

为缩短主链路，先只读脚本和导出；Python 对齐不可靠时保守粗选，不能为赶演示跳过真实来源检查。

验收：至少 3 个不同风险场景的真实授权视频跑完整三端；产物/工具版本/失败/成本可追溯；刷新可按 taskId重新显示；无隐式模拟；非法 ID/版本/区间拒绝；草稿与可确认状态分清。

3 个只是最小联调样本，不足证明质量收益。未通过则先定位输入、索引、决策或回调，不并行扩大功能。

### M2：脚本可治理与工作台完善

包含：受限编辑、版本 CAS、依赖检查与风险处理、确认快照、跨任务切换保护、历史版本、完整分页列表。

仅浏览器刷新时可从仍在运行的服务端内存重新查询；需要服务重启后保留任务/脚本时采用 MySQL 持久化并执行集成测试。元信息保留仍不等于中断执行可以恢复。

验收：双编辑不覆盖；AI晚回调不盖人工稿；修改重算时间/字幕；旧确认不可准入；所有导出同版。

### M3：素材中心与推荐

包含：系统/个人包装库、视频/图片/动画上传预览、许可与内容核实、规则召回/Agent 比选、NONE、人工替换、资源清单。

验收：先 20～30 个授权小库，适配判断/搜索成本真实记录；未知/越权资源拒绝，锚点和时间一致，不把建议当执行。

### M4：基础成片闭环

包含：只针对已验证操作的确认快照异步渲染，先原序原速硬切与可验证字幕；同页进度、预览、下载。

验收：真实结果区间、音轨、时长可对账；任务目录隔离；历史下载不变；未包含包装显式列出；渲染失败不毁脚本。

### M5：包装合成及可靠性按需演进

先验证一个模式，例如静态图 OVERLAY，再覆盖视频/动画；透明、缩放、音频、字幕图层分别测试。独立插段和转场另扩时间编译规则。

需要故障后继续时再补 Task lease/attempt、持久阶段产物、幂等受理和取消。复用任务表，不立即引入 MQ/第二套调度器。

恢复验收需真实重启/故障注入，MySQL记录存在不算恢复成功。质量未验证前不靠工程堆栈掩盖效果缺口。

## 15. 测试与效果评测

### 15.1 分层测试

| 层 | 重点 |
|---|---|
| 单元 | 区间/累计时间、ID/版本、字幕时域、硬约束、修复重校验、best候选 |
| 契约 | Python/Java/TS golden fixtures，未知字段拒绝、Long ID字符串、单位与可选字段一致 |
| Java集成 | MySQL事务/CAS、回调并发、分页、归档不可覆盖 |
| AI真实联调 | 真实 ASR/VLM/导演/QA，原文与时间来源、成本和降级 |
| 前端 | 创建/列表/切换/刷新/断网、原片定位、草稿告警、导出版本 |
| 媒体 | Range定位、不同帧率/无音轨、渲染结果实际播放与ffprobe |
| 故障后续 | 提交不确定、重复/晚回调、重启/取消、lease过期 |

### 15.2 关键回归

长声学块跨句、场景多但索引不丢区间、指代前文被删、条件/否定被删、问答依赖、恢复引入重叠、非法兜底、QA无证据、最高分非法、预算耗尽。

多任务切换旧响应、刷新后无内存状态、同项目多 SOURCE、失败回调无 plan、终态迟到progress、重复完成、目标输入未持久化、同一 requestId 重复点击。

图片无天然时长、动画无透明/不可循环、库素材失效、未知ID、超锚点、未支持包装被忽略、基础版与包装版混淆。

### 15.3 效果实验

小型版本化授权素材集，区分开发和冻结留出；不要把同一素材邻接片段分到两组。预先标注任务相关关键内容和依赖，避免以全素材保留率衡量主题提炼。

三条真实基线：简单规则、单 Agent、当前多 Agent；新脚本决策作为实验组。相同素材、主题、上限与预算，固定重复次数，保留失败，不只选最佳一次。

主要指标：

- 执行：合法引用/硬约束违反、真实任务完成、后续实际渲染与恢复。
- 内容：关键内容误删、上下文缺失、原意改变、转写/边界错误。
- 用户：定位素材时间、理解脚本时间、人工修改时间/次数。
- 包装：候选覆盖、适配/误导判断、查找时间、替换/拒绝、采用率与成本。
- 资源：端到端/阶段耗时、模型请求/重试/token/费用、降级/失败及分母。

ASR-only/VLM、QA、上下文保护、规则/Agent选材按需消融。模型自评分是诊断，不作为质量结论。

先完整主链路再做效果实验，且“跑通”与“有收益”分开。留出集原意严重回归时不推广新策略；无改善如实报告。

### 15.4 阶段验收清单

- M1：真实文件/工具 → 合法脚本 → 回调保存 → 同页展示/定位/导出；工具真实/失败/模拟可查。
- M2：编辑/保存/确认版本一致，历史和终态不覆盖，MySQL路径真实测试。
- M3：素材合法可预览，推荐有证据可拒绝，无强插和授权绕过。
- M4：固定快照 → 异步渲染 → 实际媒体检查 → 同页下载，不承诺高质量。
- M5：每个新操作/恢复能力单独提供真实测试结果。

## 16. 面试表达与待确认项

### 16.1 完成后的表达结构

业务问题：创作者不仅要浏览和筛选主素材，还要整理剪辑脚本、寻找包装并追踪长任务。  
设计取舍：先验证 Agent脚本链路；同页工作台集中操作，后台复用任务体系；模型选 ID与解释，程序负责时间、约束、版本和执行。  
异常边界：粗对齐不细切，语义告警不靠高分绕过，库素材可不选，晚回调不盖人工稿，未支持包装不冒充已执行。  
验证结果：以真实素材对照、人工修正和失败/成本数据说明收益。

所有“完成后”内容在当前阶段只能写为方案，不能写成简历成果；维持 AgentWrite 为记忆/评测/异步主线，AgentCut突出多模态与输出可控性。

### 16.2 已明确需求

素材可展示/上传/复用；任务可列表查询；创建到结果尽量同页；先真实 Agent分析生成脚本，后加功能。七列脚本格式已经确认。

### 16.3 本设计推荐取舍

1. 单页任务工作台，素材抽屉；Project与执行Task分开，不新建“超级任务”系统。
2. M1 优先只读脚本生成/定位/导出，不要求素材库或渲染先完成。
3. 第一业务边界为单主视频、用户明确主题、原序原速、合法 ID与可追溯时间。
4. M2编辑确认，M3素材推荐，M4基础成片，M5包装合成和恢复按需。
5. 现有接口/模型渐进扩展，未验证能力不展示成功，不引入无必要新框架。

完整方案等待用户评审后再拆实施计划；本轮不修改代码、不覆盖已有改动、不提交 Git。
