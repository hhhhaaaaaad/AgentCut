# AgentCut 多 Agent 剪辑架构 · 方案总结（面试版）

> 本文是 AgentCut「多 Agent 视频智能剪辑」的完整方案总结，兼顾**技术阐述**与**面试表达**。
> 适合：秋招面试前快速回顾、项目介绍、技术面答疑。

---

## 0. 一句话概括（电梯陈述）

> AgentCut 是一个**视频智能剪辑平台**：用户上传视频，系统用**多个 AI Agent 协同**——分析时间轴、抽取讲解内容、生成剪辑方案、再由质量监督 Agent 迭代优化，最终由 FFmpeg 自动剪辑成片。我的核心工作是设计了这套**「分析专家 + 导演 + 质量监督 + 确定性校验闸」的多 Agent 架构**，重点解决了「LLM 直接生成剪辑方案质量不可控」的问题。

---

## 1. 背景与痛点

**产品流程**：上传视频 → Agent 分析 → 产出可编辑剪辑方案 → 用户确认 → FFmpeg 自动剪辑 → 成片。

**最初实现是「单次 LLM 直出方案」**，存在三个致命问题：

1. **职责混杂**：一个 VLM 调用要同时输出摘要、场景描述、标签、重要性、亮点、建议六种东西，每个字段都浅、都不稳定。
2. **讲解内容名存实亡**：ASR 已拿到带真实时间戳的全文转写，但喂给模型时被截断到 800 字，导致「视频在讲什么」这个最关键的语义被丢掉。
3. **生成即定稿，零质检**：方案生成一次 `invoke` 就交付，没有「审查 → 打分 → 重写」的监督循环，错了没人纠。

**我要解决的**：把「碰运气的单次生成」升级为「有分工、有监督、有兜底的多 Agent 协同」，核心目标是**提升剪辑脚本质量**。

---

## 2. 整体架构

```
                        分析域（两个专家 + 复用 VLM）
   ┌──────────────────────────────────────────────────────┐
   │ ① 时间轴分析师        ② 讲解内容分析师      ③ 视觉语义(复用)  │
   │  TimelineAgent      NarrationAgent      vlm_understand │
   │  场景边界+ASR密度      完整转写(不截断)       Qwen3-VL 看帧  │
   │  → 章节/废话区间      → 主题/论点/关键句     → 画面描述/重要性 │
   └──────────────┬────────────────────────────────────────┘
                  ▼
        ④ 视频剪辑分析师（导演 Director）—— LLM(DeepSeek)
        汇总专家信号 + 用户目标 → 生成初版剪辑方案 Plan
                  ▼
        ⑤ 质量监督 Agent（QA Reviewer）—— LLM(DeepSeek)
        五维度打分 + 问题清单 → 不达标带 issue 喂回导演重写
                  ▼（迭代 ≤3 轮 + 时间止损）
        ⑥ 确定性校验闸（Validator）—— 纯代码，无 LLM
        12 条规则校验可执行性 → 不过则回退确定性方案（永远合法）
```

**依赖单向无环**：schemas → tools → 专家 agents → 导演 → QA/校验闸。

---

## 3. 各 Agent 职责

| Agent | 职责 | 输入 → 输出 | 模型 |
|---|---|---|---|
| ① 时间轴分析师 | 分析**视频的时间点**（时间轴结构） | 场景边界 + ASR 时间戳 → 章节 / 废话区间 / 语速密度 | 规则为主 |
| ② 讲解内容分析师 | 分析**视频在讲什么**（讲解内容） | **完整转写** → 主题 / 论点 / 关键句 / 冗余 | LLM(DeepSeek) |
| ③ 视觉语义 | 看画面，判断每个镜头的语义和重要性 | 关键帧 → 场景描述 / 标签 / 重要性 | VLM(Qwen3-VL) |
| ④ 导演（剪辑分析师） | 融合专家信号，做**剪辑决策** | 专家产物 + 用户目标 → Plan | LLM(DeepSeek) |
| ⑤ 质量监督 QA | **只挑错，不改方案** | Plan + 专家产物 → 评分 + 问题清单 | LLM(DeepSeek) |
| ⑥ 确定性校验闸 | 保证方案**可执行** | Plan → 合法 / 非法（12 条规则） | 纯代码 |

---

## 4. 质量监督闭环（核心亮点）

**五维度评分**（QA 对每个维度打 0~1 分，加权得 `overallScore`）：

| 维度 | 检查什么 | 为什么重要 |
|---|---|---|
| `timeline_continuity` | 时间轴连续、无重叠、无越界 | 不连续 → FFmpeg 报错/跳帧 |
| `content_integrity` | 核心论点/关键句是否都保留 | 避免「剪掉重点」 |
| `pacing` | 目标时长达成、变速合理 | 落实 maxDuration 约束 |
| `narration_visual_match` | 字幕与口播一致、图文对得上 | 字幕错位、图文不符 |
| `executability` | crop 坐标合法、引用存在 | 保证 render 不 500 |

**迭代循环**：`导演生成 → QA 评分 → 不达标则把 issue 清单喂回导演重写 → 再评`，直到 `overallScore ≥ 阈值(0.85)` 或迭代 3 轮 / 超时。

**关键设计：QA 只挑错，不改方案**。QA 输出的是结构化的「问题 + 修改建议」，而不是直接改方案——这样避免 QA 自己引入新错误，同时保留了完整的**审计轨迹**（每一轮为什么改、改了什么都能追溯）。

## 5. 关键设计决策与权衡

1. **职责单一、融合集中**：专家只产出各自的结构化信号，**不做决策**；剪辑决策（保留/删除/变速/时长取舍）集中在导演一个 Agent。避免多个模型对「谁重要」各执一词。

2. **确定性兜底永远存在**：任何 LLM 输出都必须过校验闸，失败回退到规则构建的确定性方案（永远合法）。**可执行性优先于智能**——这是工程上的兜底思维。

3. **schema 稳定三件套**：注入 `model_json_schema()` + Pydantic `model_validate` 硬校验 + 失败降级。三层保障 LLM 输出符合契约。

4. **重要性唯一权威**：`Scene.importance = max(视觉, 讲解)`，讲解兜下限。视觉做参考、讲解兜底，避免 VLM 和 LLM 对「谁重要」打架。

5. **内容完整性保护**：讲解分析出的关键句/高重要性论点，在时长压缩时**豁免删除**（protected 集合），并加终止条件防死循环。

**核心权衡**：
- **质量 vs 成本**：多 Agent 意味着 5~8 次模型调用（秒级→分钟级）。用「专家层薄 + QA 迭代上限 + 时间止损 + SIMULATE 全确定性」控制。
- **智能 vs 可执行**：LLM 能生成「聪明」的方案，但可能不可执行。用「prompt 硬约束 + 校验闸」双保险，宁可回退到确定性方案也不出不可执行的片。

## 6. 实现中踩的坑（面试故事素材）

这些都是真实遇到并解决的问题，面试时讲出来能体现**工程能力**：

1. **循环导入**：时间轴分析师要复用分析层的静音检测函数，直接 import 会构成 `analysis_agent ↔ timeline_agent` 循环依赖 → 抽到公共模块 `_common.py`。
2. **LLM 吐坏 JSON 导致任务标 failed**：导演生成时 JSON 解析失败会一路冒泡到顶层异常 → 包 try/except，失败返回 None 回退确定性方案。
3. **Java 判空把 JSON null 写成字符串 "null"**：`JsonNode.toString()` 对 null 节点返回字面量 `"null"` 污染数据库 → 加 `isNull()` 判空。
4. **DeepSeek 不支持 `response_format`**：`with_structured_output` 依赖它 → 改为让 LLM 输出 JSON 文本，手动 `model_validate`。
5. **时长压缩误删核心论点**：原逻辑按 importance 排序丢段，无视高亮场景 → 加 `protected_idx` 豁免 + 终止条件。
6. **transcript 800 字截断**：导致讲解内容分析名存实亡 → 讲解分析师改为吃完整转写。

## 7. 技术栈

- **AI/分析层（Python）**：LangChain + OpenAI SDK；DeepSeek(LLM)、SiliconFlow Qwen3-VL(视觉)、Qwen3-ASR(转写)；PySceneDetect(场景检测)、webrtcvad(VAD)、FFmpeg。
- **后端（Java）**：Spring Boot 3.4.3、Java 17、Maven 六模块 DDD 分层（types/api/app/domain/infrastructure/trigger）、MyBatis + MySQL。
- **前端**：React。

## 8. 面试表达指南（重点）

### 8.1 开场白（30 秒版本）

> 「这是我秋招做的一个视频智能剪辑项目 AgentCut。核心亮点是我设计了一套多 Agent 架构：两个分析专家（一个分析时间轴、一个抽取讲解内容）先理解视频，一个导演 Agent 生成剪辑方案，再用一个质量监督 Agent 对方案打五维评分、迭代优化，最后过一道纯代码的确定性校验闸保证方案一定能被 FFmpeg 执行。这套架构解决的核心问题是——LLM 直接生成剪辑方案质量不可控。」

### 8.2 高频问题 + 参考回答

**Q1：为什么用多 Agent，而不是一个 Agent 一次做完？**
> 三个原因：一是**职责单一**，分析时间轴、抽取讲解内容、做剪辑决策、质量监督是四件不同的事，拆开让每个 Agent 只做一件事，输出更稳定；二是**可独立迭代**，比如我发现「讲解内容分析」效果差，只改讲解 Agent 的 prompt，不影响其他部分；三是**质量监督需要独立的审计视角**——如果让同一个 Agent 边生成边自检，等于既当运动员又当裁判，很难发现自己的问题。

**Q2：为什么质量监督 Agent 只挑错、不改方案？**
> 防止「纠正一个错又引入一个新错」。QA 输出结构化的问题清单 + 修改建议，由导演根据清单重写。这样每一轮「为什么改、改了什么」都有据可查，形成了可追溯的审计轨迹。这也符合软件工程里「评审和修改分离」的原则。

**Q3：LLM 生成的内容不可靠，你怎么保证方案一定能执行？**
> 三层保障：第一层，prompt 里注入 JSON Schema 并写清硬性规则；第二层，输出用 Pydantic 强校验，字段不符合契约直接拒绝；第三层，也是兜底——一道**纯代码的确定性校验闸**，用 12 条规则检查时间轴连续性、裁剪坐标、变速后时长等，任何 LLM 输出都过这一关，过不了就回退到规则构建的确定性方案。**可执行性优先于智能**，宁可回退也不能产出不可执行的片。

**Q4：多 Agent 成本/延迟高，怎么控制？**
> 几个手段：分析专家里时间轴分析师用规则、不用模型；QA 迭代设上限 3 轮 + 120 秒时间止损；开发/测试时用 SIMULATE 模式全走确定性路径、不花模型 token。

**Q5：这个项目里你最有成就感的一个技术点？**
> 我认为是「质量监督闭环 + 确定性校验闸」这套组合。它把 LLM 这种「不可控的黑盒」嵌进了一个「可控的工程框架」里——LLM 负责出创意，代码负责保证正确性。这种「智能与确定性结合」的思路，我觉得是现在做 LLM 应用最需要的能力。

### 8.3 可主动讲的亮点（3~5 个）

1. **多 Agent 协同架构**：分析专家 + 导演 + 质量监督 + 确定性校验闸，职责单一、可独立迭代、有审计轨迹。
2. **质量监督闭环**：五维度结构化打分 + 迭代重写，把「脚本质量」变成可量化、可优化的目标。
3. **确定性兜底**：LLM 不可靠时的工程兜底——纯代码校验闸 + 规则方案回退。
4. **跨语言契约**：Python 产出的 Plan 通过 JSON Schema 对齐 Java 端反序列化，跨技术栈协同。
5. **真实踩坑经验**：循环导入、LLM 坏 JSON、Java null 污染、DeepSeek 兼容性等，体现解决实际问题的能力。

### 8.4 如何引导面试官到你的强项

- 面试官问「项目里做了什么」→ 主动把话题引到**架构设计**和**权衡**，而不是罗列功能。
