# 导演「删减决策」优化设计方案

> 目标：解决导演 Agent 在「保留/删除」决策上的不稳定性——过度删减、删掉核心内容、拆断句子。
> 定位：`plan_agent.py` 的导演（Director）层，不改动分析层与 QA 层的契约。
> 本文落到函数级，可直接照着写代码。

---

## 0. 背景与问题

### 0.1 实测数据（test1min.mp4，真实 ASR）

| 轮次 | 成片时长 | 保留段 | 删除段 | QA 分数 | content_integrity |
|---|---|---|---|---|---|
| 优化前 | 79.5s | 5 | 4 | 0.65 | 0.8 |
| 优化后（①②③ 导演优化后） | **43.3s** | 11 | **13** | **0.55** | **0.4** |

### 0.2 问题现象

导演「转场/float」问题解决了（①转场规则生效、transitions 归零），但「删减」暴露出新问题：

1. **删得太多**：96s → 43.3s（保留 45%），而上轮是 79.5s（保留 82%）。
2. **删掉核心铺垫**：删除了 sceneIndex 5（书/作者的引入段），导致后续「他」指代缺失。
3. **拆断句子**：删除 87.33-90.0 导致「读懂了这本书就相当于给初高中数学打…下了扎实的基础」被腰斩。

QA 的 content_integrity 维度准确抓到了这些问题（评分 0.4），说明 QA 在干活，但导演没改对。

---

## 1. 根因分析

导演删减决策不稳，本质是**缺三个「边界」+ 一个「信息传递」问题**：

| 根因 | 说明 |
|---|---|
| **「必须留」边界不完整** | `_build_hard_constraints` 只把 keySentences 加入「必须保留」，漏了 arguments.sceneIndices。sceneIndex 5 是 argument 3 的依赖场景，但不在 keySentences 里，导演「不知道」要留。 |
| **「删多少」无边界** | 导演没有「删减预算」，一次删 17%、一次删 55%，随机。 |
| **「删的最小单元」无边界** | 导演把删除边界切进了句子内部，导致句子不完整。 |
| **信息传递断裂** | 分析层（narration）已经正确识别出 arguments.sceneIndices，但这条信息没传进导演的约束，白白浪费。 |

---

## 2. 方案总览（两层）

```
第一层：Prompt 约束补全（改 _build_hard_constraints，低风险）
  ① 补全「必须保留」→ arguments.sceneIndices
  ② 加「删减预算」
  ③ 加「删除最小单元」

第二层：确定性兜底（改机制，中风险，视效果再上）
  ④ QA high 问题的确定性修复（_sanitize_plan）
  ⑤ 保留/删除决策的确定性化（架构级，暂不做）
```

**核心原则**：优先「补约束」（让导演有正确输入），而非「叠机制」（加兜底）。先做第一层，验证后再决定第二层。

---

## 3. 详细设计

### 3.1 ① 补全「必须保留」

**目标**：把论点依赖的铺垫场景也纳入保护，避免导演删掉「非关键句但承上启下」的内容。

**改动点**：`plan_agent.py` 的 `_build_hard_constraints()`，在 keySentences 循环后追加 arguments 处理。

```python
def _build_hard_constraints(self, report) -> str:
    keep_items: List[str] = []
    for h in report.highlights[:10]:
        keep_items.append(f"  sceneIndex={h.sceneIndex} ({h.start:.1f}s~{h.end:.1f}s): {h.reason}")
    narration = getattr(report, "narration", None)
    if narration:
        for ks in sorted(narration.keySentences, key=lambda k: k.importance, reverse=True)[:10]:
            keep_items.append(f"  sceneIndex={ks.sceneIndex} ({ks.start:.1f}s~{ks.end:.1f}s): {ks.text[:40]}")
        # ① 新增：高 importance 论点的依赖场景
        for arg in narration.arguments:
            if arg.importance >= 0.5:
                for si in arg.sceneIndices:
                    keep_items.append(f"  sceneIndex={si}: 论点「{arg.claim[:30]}」依赖的铺垫/内容")
    ...
```

**复杂度**：低（几行，无新依赖）。

---

### 3.2 ② 加「删减预算」

**目标**：给导演一个「删多少」的量化边界，避免删减程度随机。

**方案二选一**：

**A. 简单版（固定引导）**：在硬性规则里加一条静态指引。

```python
lines.append(
    "【删减预算】仅删除明确标注的冗余/废话段；建议成片保留源内容 60%~80%，"
    "除非冗余段占比明显高于该比例。"
)
```

**B. 进阶版（动态算冗余占比）**：从 report 计算冗余占比，动态注入「删除量上限」。

```python
def _redundancy_ratio(self, report) -> float:
    """冗余段占总时长的比例（0~1）。"""
    total = report.duration
    narration = getattr(report, "narration", None)
    if not narration or total <= 0:
        return 0.0
    redundant = sum(rd.end - rd.start for rd in narration.redundancy)
    return min(1.0, redundant / total)

# 在 _build_hard_constraints 中：
ratio = self._redundancy_ratio(report)
lines.append(
    f"【删减预算】本次识别出的冗余段约占总时长 {ratio:.0%}，"
    f"建议删除量不超过 {ratio + 0.1:.0%}（含少量过渡缓冲），不得删除非冗余内容。"
)
```

**复杂度**：A 低（一行）、B 中（加一个辅助函数）。

**推荐**：先上 A，若导演仍删减过度，再上 B。

---

### 3.3 ③ 加「删除最小单元」

**目标**：防止导演拆断句子。

**改动点**：硬性规则里加一条。

```python
lines.append(
    "【切分规则】删除边界必须对齐到完整句子/场景边界，不得把一句话拆断；"
    "segment 的 start/end 对齐到 1/30s 帧边界（整数帧）。"
)
```

**复杂度**：低（一行）。

---

### 3.4 ④ QA high 问题的确定性修复（`_sanitize_plan`）

**目标**：当 QA 抓到 high 级问题（尤其 content_integrity），不再只靠导演重写，而是确定性修复兜底。

**改动点**：新增 `_sanitize_plan(plan, report, review)`，在 `_gate` 之前调用。

```python
def _build_with_llm(self, report, target, project_id):
    ...
    # 迭代耗尽/超时 → 取历史最高分那版
    final = best_plan or plan
    final = self._sanitize_plan(final, report, self.last_quality)
    return self._gate(final, report, target, project_id)

def _sanitize_plan(self, plan, report, review) -> Plan:
    """确定性修复 QA 的 high 问题（能映射成确定性动作的部分）。"""
    if plan is None or review is None:
        return plan
    for issue in review.issues:
        if issue.severity != "high":
            continue
        if issue.dimension == "content_integrity" and issue.sceneIndex is not None:
            plan = self._restore_scene(plan, report, issue.sceneIndex)
        elif issue.dimension == "narration_visual_match":
            # fade 覆盖语音 → 去掉该 transition（硬切）
            plan.transitions = []
    return plan

def _restore_scene(self, plan, report, scene_index) -> Plan:
    """把被误删的 sceneIndex 对应区间强制恢复为 keep。"""
    scene = report.scenes[scene_index] if scene_index < len(report.scenes) else None
    if scene is None:
        return plan
    for seg in plan.timeline:
        # 该段 sourceRange 覆盖了目标场景区间 → 恢复 keep
        if (seg.sourceRange.start <= scene.start + 1e-3
                and scene.end - 1e-3 <= seg.sourceRange.end):
            seg.keep = True
    return plan
```

**复杂度**：中。核心难点是「sceneIndex → segment」映射（导演可能合并/拆分场景，导致不是 1:1）。上述实现只处理「段覆盖场景」的简单情况，复杂情况（场景被拆到多段）需按 sourceRange 范围恢复。

**边界**：`_sanitize_plan` 是「兜底」，只处理能确定性映射的 high 问题；处理不了的仍交给 `_gate` 的确定性方案兜底。

---

### 3.5 ⑤ 保留/删除决策的确定性化（架构级，暂不做）

**目标**：把「删什么、留什么」从导演剥离，导演只标注「冗余度/重要度」，代码按规则决定 keep/delete。

**改动点**（大）：
- Plan schema 的 Segment 增加可选字段 `importance` / `redundant`（或复用现有）。
- 导演 prompt 改为「只输出每个片段的冗余标注」，不再输出 keep/delete。
- 新增确定性决策函数：`keep = not redundant and importance >= threshold`。

**权衡**：
- 优点：删减决策 100% 稳定、可复现。
- 缺点：削弱「Agent 给出剪辑建议」的 LLM 决策能力，可能违背多 Agent 立意。

**结论**：**暂不做**，保留 LLM 决策，靠 ①②③④ 约束兜底。

## 4. 数据流变化

```
（现状）
分析报告 → 导演 prompt（必须保留：highlights + keySentences）→ 导演生成 Plan → QA → 循环

（改造后）
分析报告 → 导演 prompt（必须保留：highlights + keySentences + arguments.sceneIndices ①
                        + 删减预算 ② + 切分规则 ③）
        → 导演生成 Plan → QA → 循环 → 迭代耗尽
        → _sanitize_plan ④（QA high 确定性修复）
        → _gate（校验闸）→ 最终 Plan
```

## 6. 分阶段落地

1. **Phase 1（立即）**：①②③ —— 改 `_build_hard_constraints` 一个函数，重跑验证。
2. **Phase 2（视效果）**：④ `_sanitize_plan` —— 若 Phase 1 后导演仍偶尔删错，加确定性兜底。
3. **Phase 3（暂缓）**：⑤ 保留/删除确定性化 —— 架构级，等长视频章节切分一起设计。

---

## 7. 权衡与不做的事

- **不做 ⑤**：保留 LLM 决策能力，符合「多 Agent 给出剪辑建议」的项目立意。
- **优先补约束而非叠机制**：①②③ 是治本（给导演正确输入），④ 是兜底（纠错）。
- **接受 LLM 的随机性**：导演每次生成结果不同，QA 分数单次对比不完全可比；用「约束 + 兜底」把随机性收敛到可接受范围，而非追求确定性。
